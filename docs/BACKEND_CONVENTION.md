# 后端边界与新增服务约定

> 更新日期：2026-10-29。当前维护的读者前端是本地 Markdown 驱动的静态站点，没有必须运行的业务后端。

## 当前能力的归属

| 能力 | 当前实现位置 |
| --- | --- |
| Markdown、目录与元信息 | `frontend/content/` 和构建脚本 |
| 内容清单、搜索索引、标签与归档 | 构建阶段生成 |
| 页面导航、本文目录和主题 | 浏览器中的 Vue 组件 |
| 读者搜索 | 浏览器中的 MiniSearch，当前工作区已接入搜索窗口 |

启动、阅读、搜索与构建当前前端不要求启动 API 服务或数据库。当前数据形态以 [API_CONTRACT.md](API_CONTRACT.md) 为准。

## 引入后端前

只有用户明确提出运行时服务需求并批准实施后，才设计或添加后端。先说明需要解决的用户问题、已有前端或构建流程为何不足，再确定最小服务范围。

涉及评论、阅读统计、上传、在线编辑、登录等能力时，先定义：

- 数据来源、采集字段、读写边界和保存方式。
- 接口输入输出、错误行为、权限及必要的安全措施。
- 前端调用与失败状态、部署方式及验收条件。

尚未实现的服务不写成已存在的接口，不添加占位业务服务或历史数据兼容分支。使用符合新契约的测试数据验证需求。

## 文档同步

新增服务时同步本文件、[内容契约](API_CONTRACT.md)、[工程结构](PROJECT_STRUCTURE.md) 和 [文档索引](DOCUMENTATION_INDEX.md)，并在模块入口说明运行与验证方法。

端口与运行方式应在具体方案中明确，遵循用户和仓库已有固定端口约束，不能通过临时换端口规避占用。
