# 新增文章同步维护规范

新增 `docs` 或 `blog` 文章时，需要同步修改的文件清单与操作步骤。权威规则见 [文件维护准则.md](文件维护准则.md)。

## 通用命名规则

- 一级分类文件夹名：英文 slug（如 `tech-study`、`resource-sharing`）
- 二级目录、文章文件名、页面标题、正文：使用中文
- `site/build`、`site/.docusaurus` 是构建产物，不手动修改

docs 文章推荐 Front Matter：

```md
---
title: 文章标题
authors: lucan
date: 2026-06-29T10:00:00+08:00
last_update:
  date: 2026-06-29T10:00:00+08:00
  author: lucan
description: 文章说明
sidebar_position: 1
---
```

blog 文章推荐 Front Matter：

```md
---
slug: article-slug
title: 文章标题
authors: lucan
date: 2026-06-29T10:00:00+08:00
last_update:
  date: 2026-06-29T10:00:00+08:00
  author: lucan
description: 文章说明
tags:
  - 标签一
  - 标签二
---
```

## docs 同步清单

docs 文章变动需要同步的文件按层级如下（详见 [文件维护准则.md](文件维护准则.md)）：

- `site/docs/index.md`：docs **总目录页**，记录所有一级分类、二级分类、文章。**所有 docs 变动都要同步**。
- `site/docs/<一级分类>/index.md`：一级分类目录页，记录该分类下的全部二级分类与文章。
- `site/docs/<一级分类>/<二级分类>/index.md`：二级分类目录页，**每个二级分类都必须有 `index.md`**，创建新二级分类时同步创建。
- `site/sidebars.ts`：docs 分类和文章变动都要同步。
- `site/docusaurus.config.ts`：**只有 docs 一级分类变动才改**（新增/删除/重命名/改显示名）。
- `admin/backend/data/content-schema/categories.yml`：docs 一级分类新增/删除/重命名/改显示名都要同步。
- `admin/backend/data/registry_index.sqlite3`：docs 分类和文章变动完成后都要重建/刷新。

### 新建 docs 文章（分类已存在）

1. 新建文章文件，例如 `site/docs/tech-study/java-interview/java-basic/java-vs-cpp.md`。
2. 修改 `site/sidebars.ts`，把文章 ID 加到对应二级分类的 `items` 中：

   ```ts
   'tech-study/java-interview/java-basic/java-vs-cpp'
   ```

3. 同步更新三个 `index.md`：所属二级分类、所属一级分类、docs 总目录页。
4. 刷新 `registry_index.sqlite3`。

### 新建二级分类

1. 新建二级目录与文章文件。
2. 新建二级分类目录页 `index.md`。
3. 修改 `site/sidebars.ts`，在已有一级分类 `items` 中新增 `category`：

   ```ts
   {
     type: 'category',
     label: '流程与协作',
     collapsed: false,
     items: ['dev-standards/workflow/single-full-stack-efficient-workflow'],
   }
   ```

4. 同步更新一级分类 `index.md` 和 docs 总目录页 `index.md`。
5. 刷新 `registry_index.sqlite3`。

### 新建一级分类

1. 新建一级目录、二级目录、文章文件。
2. 新建二级分类 `index.md`。
3. 新建一级分类 `index.md`。
4. 修改 `site/sidebars.ts`，新增一个 sidebar 分组：

   ```ts
   devStandardsSidebar: [
     {
       type: 'category',
       label: '开发规范',
       collapsed: false,
       items: [
         {
           type: 'category',
           label: '流程与协作',
           collapsed: false,
           items: ['dev-standards/workflow/single-full-stack-efficient-workflow'],
         },
       ],
     },
   ],
   ```

5. 修改 `site/docusaurus.config.ts`，在顶部"知识库"下拉菜单加入新一级分类入口：

   ```ts
   {
     label: '开发规范',
     to: '/docs/dev-standards/workflow/single-full-stack-efficient-workflow',
   }
   ```

6. 修改 `categories.yml`，新增分类。
7. 更新 docs 总目录页 `index.md`。
8. 刷新 `registry_index.sqlite3`。

### 移动/重命名 docs 文章

1. 移动文章文件。
2. 修改 `site/sidebars.ts`，删除旧文章 ID，加入新文章 ID。
3. 全站检查并替换旧链接（`site/docusaurus.config.ts`、其他文章、各级 `index.md` 目录页）。
4. 刷新 `registry_index.sqlite3`。

## blog 同步清单

blog 文章变动需要同步的文件如下：

- `site/blog/index.md`：blog **总目录页**，记录所有一级分类、所有 blog 文章。**所有 blog 变动都要同步**。
- `site/blogSidebars.ts`：blog 分类和文章变动都要同步（一级分类变动、文章新增/删除/重命名/移动、标题/slug/date 等影响侧边栏展示的字段变化）。
- `site/docusaurus.config.ts`：**只有 blog 一级分类变动才改**。
- blog **没有二级分类**，一级分类目录下**不需要 `index.md`**，创建新分类时只建目录。
- `admin/backend/data/content-schema/categories.yml`：blog 分类变动同步；文章落到新分类时确保该一级分类已写入。
- `admin/backend/data/content-schema/tags.yml`：blog 文章涉及新标签时同步。
- `admin/backend/data/registry_index.sqlite3`：blog 分类和文章变动完成后都要重建/刷新。

### 新建 blog 文章（分类已存在）

1. 新建文章文件，建议命名 `YYYY-MM-DD-slug.md`。
2. 确认 Front Matter 完整：`slug`、`title`、`authors`、`tags`、`description`、`date`。
3. 更新 `site/blog/index.md` 总目录页。
4. 更新 `site/blogSidebars.ts`。
5. 如果涉及新标签，写入 `tags.yml`。
6. 刷新 `registry_index.sqlite3`。

### 新建 blog 一级分类

1. 新建分类目录（**不需要 `index.md`**）。
2. 修改 `site/docusaurus.config.ts`，在顶部"博客"下拉菜单加入口：

   ```ts
   {
     label: '重建个人技术站',
     to: '/blog/site-rebuild',
   }
   ```

3. 修改 `categories.yml`，新增分类。
4. 后续按"新建 blog 文章"流程加入文章。
5. 更新 `site/blog/index.md` 总目录页。
6. 刷新 `registry_index.sqlite3`。

### 新增博客作者

如果 `authors` 不是已有的，修改 `site/blog/authors.yml`：

```yml
newAuthor:
  name: 作者名
  title: 作者说明
  url: https://example.com
  image_url: https://example.com/avatar.png
```

## 检查清单

docs 文章：

- 文件路径为英文 slug，Front Matter 含 `title`、`authors`、`date`、`last_update`、`description`、`sidebar_position`。
- 已在 `site/sidebars.ts` 登记文章 ID。
- 已同步三个 `index.md`（二级分类、一级分类、docs 总目录页）。
- 新一级分类已更新 `docusaurus.config.ts` 和 `categories.yml`。
- 移动文章已替换全站旧链接。
- 已刷新 `registry_index.sqlite3`。

blog 文章：

- 文件名 `YYYY-MM-DD-slug.md`，Front Matter 含 `slug`、`title`、`authors`、`date`、`last_update`、`description`、`tags`。
- `authors` 已存在于 `site/blog/authors.yml`。
- 已同步 `site/blog/index.md` 和 `site/blogSidebars.ts`。
- 新标签已写入 `tags.yml`。
- 已刷新 `registry_index.sqlite3`。

最终验证：

```bash
cd site
npm run build
```

构建报 broken links 时优先检查：

- `site/sidebars.ts` 中 docs 文章 ID 与真实路径是否一致。
- `site/blogSidebars.ts` 中 blog 文章信息是否一致。
- `site/docusaurus.config.ts` 中 `to` 是否与文章路由一致。
- 各级 `index.md` 目录页链接是否仍指向有效路径。
