# site AI 内容归档准则

本文件用于给新对话窗口中的 AI 快速理解 `E:\A-Code\xiaocancoding\site` 的内容结构、命名规范和新增文章时的判断流程。

当用户提供一篇文章内容，并要求 AI 读取本准则后给出归档建议时，AI 应先阅读本文件，再判断文章应该进入 `docs` 还是 `blog`，并给出分类、命名和 Front Matter 建议。

## 站点内容模块

`site` 当前主要有两个内容模块：

- `site/docs`：知识库。用于长期有效、结构化、可持续维护的技术笔记、教程、规范、项目沉淀、资源整理。
- `site/blog`：博客。用于时间线文章、阶段记录、观点表达、踩坑复盘、个人成长随笔。

判断口诀：

```text
docs 做成长期知识库
blog 做成阶段时间线
```

## docs 命名规范

### docs 一级分类

- 路径目录使用英文 slug，推荐小写 kebab-case，例如 `tech-study`、`project-practice`、`resource-sharing`。
- 显示名称使用中文，例如“技术研习”“项目实战”“资源分享”。
- 每个一级分类目录必须有 `index.md`，作为该一级分类的目录页。
- 新建一级分类时，优先判断是否能归入现有一级分类；只有主题长期稳定且现有分类明显不合适时才新建。

### docs 二级分类

- 二级分类目录使用清晰中文或专有名词原名，例如 `AI 探索`、`Jetson Orin Nano`、`开发工具入门`。
- 二级分类名称应表达一个稳定专题，不要用临时状态词，例如“杂项”“待整理”“新文章”。
- 每个二级分类应有明确边界：同一系列文章尽量放在同一个二级分类下。
- 如直接手动维护 `site/docs`，新建二级分类时应同步创建该二级分类目录页 `index.md`；若通过管理后端添加文章，也要确保后台同步生成或维护对应目录信息。

### docs 文章

- 文章文件名使用中文短标题或清晰专有名词，不加日期，例如 `Docker常用命令.md`、`单人全栈开发高效流程.md`。
- `title` 使用完整展示标题，可以比文件名更完整。
- `description` 写 1 句摘要，说明文章解决什么问题或覆盖什么内容。
- `sidebar_position` 用于控制同一二级分类下的展示顺序，新增文章应建议一个合适数字。
- 图片资源建议放在文章同级的 `<文章名>-imgs` 目录中，例如 `Ollama部署LLM-imgs`。

docs Front Matter 模板：

```md
---
title:
authors: lucan
date:
last_update:
  date:
  author: lucan
description:
sidebar_position: 1
---
```

## blog 命名规范

### blog 一级分类

- `blog` 只有一级分类，没有二级分类。
- 一级分类目录优先使用中文显示名，例如 `AI观察`、`随笔感想`。
- 新建 blog 分类前，优先判断是否能归入现有分类。
- 新分类必须能容纳一组持续产生的时间线文章，不要为单篇文章创建过窄分类。

当前推荐分类含义：

- `AI观察`：AI 行业观察、AI 工具体验、AI 对工作方式和行业结构的影响。
- `随笔感想`：建站记录、成长复盘、阶段总结、个人表达。

### blog 文章

- 文章文件名使用中文短标题或 `YYYY-MM-DD-短slug.md` 均可；若用户没有指定，AI 推荐使用中文短标题，保持与当前实际文章一致。
- Front Matter 中的 `slug` 决定最终 URL，建议简短、可读、稳定，不带日期。
- `title` 使用完整展示标题。
- `date` 是发布时间，`last_update.date` 是最近更新时间。
- `tags` 使用中文或常见英文技术词，优先复用已有标签；新标签应简洁，不要过细。
- blog 文章不设置 `sidebar_position`。

blog Front Matter 模板：

```md
---
slug:
title:
authors: lucan
date:
last_update:
  date:
  author: lucan
description:
tags:
---
```

## AI 归档判断流程

当用户提供一篇文章内容，并让 AI 读取本准则后给出放置建议时，AI 必须按以下流程输出：

1. 判断模块：建议放入 `docs` 或 `blog`，并用 1-2 句话说明原因。
2. 判断分类：说明建议使用哪个现有一级分类；如果需要新建一级分类，说明为什么现有分类不适合。
3. 判断二级分类：如果放入 `docs`，说明建议使用哪个现有二级分类；如果需要新建二级分类，给出新二级分类名称和原因。如果放入 `blog`，明确说明 blog 没有二级分类。
4. 给出文章命名：包括建议文件名、建议标题、建议 slug（blog 必填，docs 可不填）。
5. 给出 Front Matter：按 `docs` 或 `blog` 模板填写完整建议值。
6. 给出目录更新建议：说明这篇文章加入后，本准则中“当前目录”应该新增到哪一行。

AI 不应直接替用户把文章归档到一个全新分类，除非文章主题无法自然落入现有分类，且新分类具备长期扩展价值。

## 维护本准则的规则

每次用户采纳 AI 建议，并通过管理后端手动把文章加入 `site` 后，应同步维护本文件：

- 新增 `docs` 文章：把文章加入对应 `docs` 一级分类、二级分类的文章列表。
- 新增 `docs` 二级分类：在对应一级分类下新增二级分类标题，并列出文章。
- 新增 `docs` 一级分类：在“docs 当前目录”的一级分类表中新增一行，并补充对应分类章节。
- 新增 `blog` 文章：把文章加入对应 blog 一级分类的文章列表。
- 新增 `blog` 一级分类：在“blog 当前目录”中新增分类标题，并列出文章。
- 修改文章标题、文件名、分类或 slug 后，也要同步更新本文件中的目录快照。

维护时只更新真实已经加入 `site` 的内容；不要把“计划新增但尚未入库”的文章写入当前目录。
