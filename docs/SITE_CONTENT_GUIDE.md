# Markdown 内容写作与维护

> 更新日期：2026-10-29。内容事实源为 `frontend/content/`，三栏使用同一套 Markdown 渲染。

## 内容放在哪里

| 目录 | 内容 |
| --- | --- |
| `frontend/content/knowledge/` | 知识笔记、教程、参考资料和问题记录 |
| `frontend/content/blog/` | 随笔、阶段思考和实践复盘 |
| `frontend/content/projects/` | 自有项目、二次开发项目与推荐工具介绍 |

目录代表分类，一篇 Markdown 对应一个独立内容页，可任意嵌套。新增内容不需要同步路由、导航配置或分类清单。

```text
某个分类/
├── README.md
├── 01-我的文章.md
├── 01-我的文章-images/
│   └── 截图.png
└── 02-另一篇文章.md
```

## 页面与目录规则

- 三栏下拉菜单显示首页和一级分类；内部分类与文章由分类页和侧栏进入。
- 栏目首页有非空 README 时显示介绍，侧栏列一级分类；无 README 或正文为空时自动显示直属分类和直属文章。
- 内部分类页显示该目录介绍、直属子分类和直属文章，不平铺更深层文章。
- 每个 Markdown 各自生成文章页；文章侧栏只展开所属一级分类的目录树。
- `README.md` 不区分大小写，专门作为目录介绍，不作为普通文章进入列表、标签、归档和文章搜索。
- 三栏中的空分类保留入口；以 `.` 或 `_` 开头的文件、目录不作为内容发布。
- 文件夹及文件名构成 URL。移动、重命名后更新相关链接，不为旧地址添加历史数据兼容分支。

## 命名、标题和排序

- 需要固定次序时用 `01-`、`02-` 等数字前缀，目录也可使用。
- 目录显示名称会去掉数字前缀，URL 保留实际名称。
- 文章标题依次取 frontmatter 的 `title`、正文首个 `# 一级标题`、去掉数字前缀的文件名。
- 默认按目录顺序排序，也可在分类页按 `date`（开始写作时间）切换到“创建时间”排序，无日期文章排在有日期文章之后；`sticky: true` 的文章置顶。
- 前后篇导航按同一直属目录内的文章次序生成。

## 统一 YAML 头部（frontmatter）

`frontend/content/` 下新建的普通 Markdown 文章必须使用以下六字段模板，知识库、博客、项目和以后新增栏目共用同一规范。字段全部保留，顺序固定。目录介绍 `README.md`（不区分大小写）、工程说明、设计文档和 `AGENTS.md` 不要求使用文章模板。

以下时间仅为格式示例，创建文章时必须换成真实时间。

```markdown
---
title: "我的文章"
date: "2026-10-29T10:00:00+08:00"
updated: "2026-10-29T10:00:00+08:00"
description: "用一两句话概括文章内容。"
tags: ["学习笔记", "工程实践"]
sticky: false
---

# 我的文章

## 使用方法

### 操作步骤
```

| 字段 | 类型 | 填写规则 |
| --- | --- | --- |
| `title` | 字符串 | 必填且非空，与正文一级标题一致，不含文件名的排序前缀 |
| `date` | 时间字符串 | 文章首次开始写作的时间，创建后保持不变，不代表首次发布或文件复制时间 |
| `updated` | 时间字符串 | 最近一次内容修改时间，新建时与 `date` 相同，后续修改正文或文章元信息时更新，不早于 `date` |
| `description` | 字符串 | 必填且非空，用一两句话概括实际内容，作为列表和搜索摘要 |
| `tags` | 字符串数组 | 使用有意义、不重复的标签，没有标签时填 `[]` |
| `sticky` | 布尔值 | 默认 `false`，确需置顶时填 `true`，不加引号 |

### 格式与维护规则

- YAML 必须位于文件最顶部，以独立的 `---` 行开始和结束；使用空格缩进，不使用 Tab，不重复字段。
- 字符串统一使用双引号；内容中的双引号和反斜杠按 YAML 双引号字符串规则转义。`tags` 使用示例中的行内数组格式。
- `date`、`updated` 统一为 `YYYY-MM-DDTHH:mm:ss+08:00`，保留秒和北京时间时区；文章页显示到分钟，源文件仍保留秒。
- 新建时记录真实开始写作时间；内容修改时维护 `updated`，不要只因为复制、移动、重命名、重新构建或部署而改写日期。
- 导入已有文章时保留已知的真实时间；原文只有发布日期时，不能直接认定为开始写作时间。缺失的历史时间先向作者确认，不用当前时间或文件时间冒充。
- 字数和阅读时长由内容管线计算，不写进 YAML。中文按字、英文和数字按词统计，排除常见 Markdown 标记、图片、围栏代码块和 HTML 注释。阅读时长按每分钟 300 字向上取整，至少 1 分钟，属于估算值。
- 新文章不使用旧站字段 `authors`、`slug`、`sidebar_position`，也不新增 `created`、`createdAt` 等同义日期字段。作者当前由页面统一展示，路径和排序由目录、文件名决定。

### 写作要求与当前程序行为

六字段必填是新文章的写作要求。站点内容扫描器不自动补齐或回写 YAML；桌面管理端新建普通文章会自动生成模板并在保存时校验，已有完整六字段文章实际修改时维护 `updated`，保留 `date`。README 等说明文档豁免，历史文档不批量补日期。现有站点解析器仍支持标题和摘要缺省：标题回退到正文标题或文件名，摘要从正文截取。日期只读取 YAML，缺失或无效时文章页显示“未记录”，不使用文件创建、修改时间，也不以 `date` 冒充缺失的 `updated`。

普通文章页统一展示“阅读约 N 分钟”“全文 N 字”“创建于”“更新于”。创建和更新时间按北京时间显示到分钟，即使两者相同也同时显示；源文件继续保留秒。未填写创建时间的文章仍可正常阅读和搜索，不进入日期归档；已有历史日期的真实性需由作者确认，不自动批量改写。

鼠标悬停或通过 Tab 聚焦四项信息时，显示黑底白字、底部带小三角的说明气泡，依次为“预计阅读时长 ⏳”“文章字数 📝”“写作日期 📅”“最新更新时间 🕒”。

## 图片约定

新内容统一使用 `文章名-images/`，文章名是完整文件名去掉 `.md`。例如 `01-我的文章.md` 对应 `01-我的文章-images/`，`我的文章.md` 对应 `我的文章-images/`。

```markdown
![截图说明](./01-我的文章-images/截图.png)
```

- 图片与 Markdown 一起保存在 `content/` 内，复制文章时连同配图目录一起复制。
- 引用使用相对路径，支持中文、空格、`../` 和 `%20`；不要使用电脑上的 `E:\...` 绝对路径。
- 支持 PNG、JPG/JPEG、GIF、SVG、WebP、AVIF、BMP、ICO；PDF 用普通附件链接。
- 配图目录只放图片等资源，不放 Markdown 文章；仅含资源的目录不会作为分类。
- 网络图片可用标准 Markdown 地址引用，显示取决于图片地址是否可访问。
- `-images` 是当前写作命名约定；不据此声称扫描器已实现所有后缀的专门过滤。

## 文章互链与锚点

```markdown
[另一篇](./02-另一篇文章.md)
[当前分类介绍](./README.md)
[上一级介绍](../README.md)
[安装步骤](#安装步骤)
```

`.md` 链接按源文件位置解析为文章地址，README 链接解析为目录地址，可保留查询参数和锚点。中文标题锚点保留中文，英文转小写，空格转 `-`；同名标题依次追加 `-1`、`-2`。

## 右下角“本文目录”

- 使用 `## 二级标题` 和 `### 三级标题` 组织正文，它们会自动进入目录。
- `**章节名称**` 是加粗文字，不是标题，不会生成目录项。
- 没有二、三级标题的文章不显示按钮；一级标题、四级及更深层级的标题不单独作为目录项。
- 三栏文章共用右下角按钮和目录跳转；窄屏使用底部操作栏。
- 分类介绍 README 不使用文章页的浮动目录。

## 项目介绍内容

每个项目写一篇 Markdown，可按实际内容组织「功能亮点、链接、致谢、参与贡献」等二级标题。

- 官网、下载、源码、反馈、安全及贡献入口按项目实际情况填写，不编造链接或承诺。
- Fork 项目注明来源及自己的二次开发范围，保留原作者和许可说明。
- 推荐工具说明用途、使用场景和可核实的获取入口，不将规划功能写成现有能力。

## 更新与检查

1. 新建普通文章时填写完整六字段 YAML；修改文章时保留 `date` 并维护 `updated`，同时维护图片和文章互链。
2. 开发模式会监控内容、目录及资源变更并刷新；检查分类、文章、图片及本文目录。
3. 内容规则或路径修改后运行相关测试；发布前构建并部署 `frontend/dist/`。
4. 不手工编辑 `frontend/src/generated/`；线上更新不能仅靠复制到本地。

标准 Markdown 是当前写作范围。Obsidian 的 `![[图片.png]]` 等双链需改为标准写法；不执行 MDX JSX，不转换原始 HTML 内的资源地址，也不直接渲染 Word 文件。
