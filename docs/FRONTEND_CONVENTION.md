# 前端开发约定

> 更新日期：2026-10-29。技术栈及命令见 [frontend/README.md](../frontend/README.md)，公共约束见 [GLOBAL_STANDARDS.md](GLOBAL_STANDARDS.md)。

## 修改入口与复用

- Vue 3 单文件组件采用现有 Composition API、TypeScript 和组件样式组织方式。
- 内容与站点 UI 分开维护：文章正文写入 `frontend/content/`；展示逻辑写入 `frontend/src/`。
- 先查 `views/`、`components/`、`composables/` 是否已覆盖需求；不要复制三套栏目页面或新增手工导航表。
- 复用 `useContent`、`contentHref`、`contentPath`、`resolveContentUrl` 和 `sidebarNodes`，避免重复拼接中文路径。
- 每次改动兼顾读者操作、开发维护和 Agent 定位成本；禁止为历史数据新增兼容分支。

## 三栏统一展示

知识库、博客、项目通过同一内容路由、分类组件、文章组件与 Markdown 渲染器工作。

| 页面 | 当前行为 |
| --- | --- |
| 栏目首页有非空 README | 主区域展示 README，侧栏显示一级分类 |
| 栏目首页无 README 或正文为空 | 自动展示栏目标题、直属分类和直属文章 |
| 内部分类页 | README（如有）后列直属子分类、直属文章，不平铺后代文章 |
| 独立文章页 | 共用标题、作者、日期、字数、正文、阅读进度、本文目录和前后篇导航 |

- 三栏下拉菜单只列首页和直属一级文件夹；一级以内的子目录与文章通过分类页和侧栏访问。
- 进入一级分类及其文章后，侧栏只显示所属一级分类的目录树。
- 三栏空分类可导航，图片等资源目录不作为内容分类。
- 新建一级内容目录可生成其他栏目；目前三栏的逐级规则由 `isHierarchicalSection` 指定，不宣称其他栏目已采用相同行为。
- `/about` 是固定 Vue 页面；标签、归档工具页在同名内容栏目不存在时启用。

## Markdown 与本文目录

- Markdown 渲染统一使用 `MarkdownRenderer.vue`；资源解析以 Markdown 源文件位置为基准。
- 文章首个一级标题与页面标题相同时由渲染器去重，不修改源文章来适配页面重复标题。
- 正文使用真正的 `##`、`###` 标题。`FloatToc.vue` 只收集这两级标题；没有对应标题时不显示“本文目录”按钮。
- 桌面按钮固定在右下角，窄屏显示在底部操作栏；展开、章节跳转、关闭、Esc 和焦点行为应可用。
- 图片命名与写作规则统一引用 [SITE_CONTENT_GUIDE.md](SITE_CONTENT_GUIDE.md)。

## 主题、布局与可访问性

- 使用 `tokens.css` 与现有主题变量表达背景、文字、边框和强调色；避免局部引入另一套配色体系。
- 浅色、深色和窄屏都要检查对比度、换行、溢出、按钮可达性和正文遮挡。
- 交互控件使用语义化按钮、链接和表单标签；保留键盘操作、可见焦点及合适的 ARIA 状态。
- 保持正文可读宽度、代码块滚动和图片缩放；不要用固定页面宽度破坏响应式布局。
- 动画与滚动尊重用户的减少动态效果偏好。

## 读者搜索

当前工作区已包含 `Navbar.vue` 搜索入口、`SearchDialog.vue` 和 `composables/search.ts`，使用 MiniSearch 在浏览器内查询。它属于本地实现状态，不代表已提交或部署。

- 第一次打开窗口时动态加载检索模块与生成索引，无需后端。
- 检索标题、标签、摘要及处理后的正文，保留代码关键词；多个关键词采用 AND，标题权重最高。
- 英文忽略大小写并支持前缀匹配；中文使用单字及相邻双字分词；最多展示 30 条结果。
- 提供空输入、加载、失败重试和无结果状态，结果显示标题、摘要及栏目位置。
- 输入聚焦、Tab、Enter、Esc、遮罩关闭、滚动锁定和关闭后焦点恢复需验证。
- 索引与页面在内容变更后同步更新；变更字段时同步 [API_CONTRACT.md](API_CONTRACT.md)。

## 开发与验收

在 `frontend/` 使用 `pnpm dev`，固定 `http://127.0.0.1:3400/`。端口占用先核对进程来源，不换端口。

- 路径、目录、排序和内容扫描改动：运行相关 Node 回归测试。
- TypeScript 或 Vue 行为改动：运行 `pnpm test` 和 `pnpm build`，按实际风险检查受影响页面。
- 界面改动：浏览器检查浅深主题、桌面窄屏、键盘与核心跳转；不以构建成功代替交互验证。
- 文档修改：核对源码、相对链接和差异，不为了纯文档重复构建。
- 构建目标是 `frontend/dist/`；GitHub Pages 工作流使用 Pages 返回的 base_path 构建。History 路由与资源遵循该 base，构建阶段为已知分类、文章和工具页生成静态目录入口；上线需单独验证发布结果，不能把本地通过视为线上生效。
