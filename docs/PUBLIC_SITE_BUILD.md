# 公开站静态构建与系列专题

## 需求与边界

- 读者打开已有文章地址时，服务器直接返回正文、标题和摘要。浏览器启用 JavaScript 时接管交互，禁用时仍能阅读正文和访问链接。
- 发布域名明确配置后，生成 canonical、Open Graph URL、`sitemap.xml` 与 RSS 2.0 订阅源。内容事实源仍是 `frontend/content/`。
- 系列可跨栏目编排，文章继续使用原地址和直属目录前后篇。系列有独立列表、详情和文章入口。

## 构建契约

- `SITE_URL` 是站点公开 HTTP(S) origin，例如 `https://example.com`。部署前缀由 Vite `--base` 提供，例如 `/xiaocancoding/`。两者组合得到完整 URL，页面 canonical 使用目录尾斜杠。
- 未设置 `SITE_URL` 时仍构建正文，日志给出提示，省略绝对 URL 元数据、站点地图和 RSS。显式填写了无效地址时构建报错。
- 首页、分类、文章使用同一份 Vite 构建后的 HTML 模板。静态正文沿用 ByteMD 的清理流程、站内路径规则和 GFM 表格等格式，基础版式由站点全局 CSS 提供。禁用脚本时，公式保留文本，Mermaid 保留代码块。启用脚本后由 Vue 接管交互，现有插件继续渲染高亮、公式和图表。
- RSS 收录 `blog/` 下有效 `date` 的普通文章，按创建时间倒序，同时间按路径排序。条目使用标题、文章原地址与摘要。站点地图列出首页、公开的分类和文章，以及系列页。文章的 `lastmod` 仅来自有效的 `updated`。
- 现有 Pages 外壳写入应先完成，静态内容写入随后补充正文。发布环境应把已确认的公开 origin 显式传给构建进程，例如在 GitHub Actions 的构建步骤中把仓库变量 `vars.SITE_URL` 映射到环境变量 `SITE_URL`。

```powershell
cd frontend
$env:SITE_URL = 'https://example.com'
pnpm build --base /xiaocancoding/
```

## 系列内容契约

文章前六个 YAML 字段继续按内容指南的顺序填写。需要加入系列时，在 `sticky` 后附加可选字段：

```yaml
series:
  id: "vue-notes"
  title: "Vue 学习笔记"
  order: 1
```

`id` 使用小写英文字母、数字和单个连字符，最长 64 字符。同一 `id` 的 `title` 必须一致，`order` 是不重复的正整数，按数值升序展示。留出顺序间隔可在以后插入文章。README 目录介绍不参与系列。只使用普通 Markdown 的文章可省略该字段。系列入口为 `/series/`，详情为 `/series/<id>/`。已有 `content/series/` 栏目拥有该地址，启用系列前需要处理地址冲突。

## 实施计划与验收

1. 用真实内容夹具覆盖静态正文、安全清理、SEO、RSS 和子目录地址。验证根目录与子目录生产构建，检查 HTML 能离开客户端脚本独立阅读。
2. 在扫描阶段解析系列元信息，构建可排序索引。用跨目录文章、历史文档和无效 YAML 验证边界，再接入系列路由、静态页面和文章入口。
3. 跑完整前端测试和构建，检查发布文件、静态资源与导航，并对照用户工作区已有静态入口的集成顺序。

需求、方案、契约与架构自检通过后实施。构建层只生成可公开的页面和订阅文件，客户端继续读取同一份内容清单。集成与代码自检以测试、构建产物和差异检查为依据。
