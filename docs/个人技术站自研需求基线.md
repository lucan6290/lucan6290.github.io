## 一、需求背景与动因

- **现状**：个人技术站部署于 GitHub，当前基于固定框架（Docusaurus）。
- **自研动因（已确认的两大痛点）**：
  - **痛点 A —— 导航 / 层级需手动配置**：新建目录后还要同步修改多处配置（如 `docusaurus.config.ts`、`index.md`、`sidebars.ts`、`categories.yml`、索引库）才能显示。多点同步，极易遗漏。
  - **痛点 B —— 更新 / 构建 / 发布笨重**：修改一个文档需要重新构建很久。
- **价值主张（一句话）**：一个"本地 MD 目录即站内层级"的内容站——新建目录 / 文件即自动生成对应页面，**零配置导航**，改文档即时反映。
- **事实源**：本地 Markdown 是唯一内容源，站点为其只读呈现；现有 MD 内容由用户自行迁移，不在本项目职责内。

## 二、内容模型（严格树状）

- **树状结构**：一篇笔记**有且仅有一个归属位置**（目录层级），不允许一篇同时属于两个分类。
- **层级映射**：
  - 任意层目录 → 站上对应一个**分类页**（top 页 / 一级 / 二级 …），页面内容为**该分类下条目的列表**；
  - 分类下的 `.md` → 一个**内容页**（叶子节点）。
  - 层级**可任意嵌套**，嵌套深度不做限制。
- **并行聚合机制**：分类解决"归属位置"（严格树），标签（来自每篇 frontmatter）解决"跨分类聚合"，两者并存互不冲突。
- **排序规则**：支持 **数字前缀排序** 与 **创建 / 修改日期排序** 两种方式，均可切换；**置顶项恒优先**于常规排序。

## 四、排序与元信息

### 4.1 元信息字段（frontmatter）

| 字段 | 说明 |
|---|---|
| `title` | 文章标题 |
| `date` | 发布时间 |
| `updated` | 更新时间 |
| `tags` | 标签（驱动标签聚合页） |
| `description` | 摘要 |
| `sticky` / 置顶 | 是否置顶（恒排最前） |

### 4.2 排序交互默认值（已确认）

| 决策点 | 默认值 |
|---|---|
| 排序默认态 | 默认**数字前缀**排序（贴合目录语义），日期排序可随时切换 |
| 置顶与排序 | 置顶项永远排在同分类最前，不参与切换 |
| 上一篇/下一篇范围 | 同分类内按当前排序顺序衔接，跨分类不跳转 |
| 评论区 | 支持**匿名可评**，无需登录即可发言 |
| 归档形态 | 按"年 → 月"层级聚合，点击月份进入当月条目列表 |
| 暗色切换 | 跟随系统 + 手动按钮，手动选择优先并记忆 |
| 搜索范围 | 全站范围，不分分类 |

## 五、边界条件（明确不做，防范围蔓延）

- 不做在线登录、后台在线编辑、多用户、权限体系——本地 MD 仍是唯一事实源，站点侧只读。
- 不做一键发布到第三方平台（GitHub 仍作为承载 / 发布载体，"发布"不设计为站点自身功能）。
- 不做可视化"拖拽建站"或页面布局编辑器。
- 不做除 MD 外的富文本编辑入口。
- 阅读统计为每篇累计阅读量展示，不做复杂分析报表。

## 六、验收口径（"做完"的可量化定义）

1. 在站点内容目录**新建一个目录** → 刷新后自动出现对应分类页，**无需任何配置**；
2. 在任意分类下**放入一篇 .md** → 该分类列表出现该篇、点击可进入详情页；
3. **嵌套任意层目录** → 逐级自动生成分类页，层级正确；
4. **修改一篇 .md 内容** → 重新构建后页面更新，元信息正确展示；
5. 代码块、公式、Mermaid 图表在详情页正常渲染；
6. **排序方式切换**（数字前缀 / 日期）即时生效，置顶项始终置顶；
7. **全文搜索**能命中标题与正文，结果可点击跳转；
8. 标签点击 → 进入标签聚合页，列出该标签下全部条目；
9. 归档按时间维度聚合、最近更新按更新时间倒序，均正确；
10. 暗色模式切换即时生效并记忆；大纲、阅读进度、上一篇/下一篇均可用；
11. 评论可发表、可见；阅读数随访问递增。
