# 新增文章与关联内容维护

> 更新：2026-10-29。三栏采用目录驱动，不需要手工同步导航配置。

## 新增文章

1. 选择 `frontend/content/knowledge/`、`blog/` 或 `projects/` 下的合适分类。
2. 创建独立 Markdown，按需要使用数字前缀，并填写 [内容指南](../SITE_CONTENT_GUIDE.md#统一-yaml-头部frontmatter) 规定的完整六字段 YAML；`date` 记录开始写作时间，`updated` 初始与其相同。
3. 配图放入同级 `文章名-images/`，在正文使用相对路径引用。
4. 使用二、三级标题组织章节，打开文章检查右下角“本文目录”。
5. 在分类与侧栏确认入口、摘要和排序，检查图片及文章互链。

## 示例

```text
frontend/content/projects/01-我的项目/
├── 04-示例项目.md
└── 04-示例项目-images/
    └── 预览.png
```

```markdown
---
title: "示例项目"
date: "2026-10-29T10:00:00+08:00"
updated: "2026-10-29T10:00:00+08:00"
description: "介绍示例项目的用途和主要功能。"
tags: ["项目实践"]
sticky: false
---

# 示例项目

## 功能亮点

项目功能说明。

![项目预览](./04-示例项目-images/预览.png)
```

示例日期需替换为真实时间。后续修改正文或元信息时更新 `updated`，保留 `date`；移动、复制、重命名或部署本身不改写日期。历史开始写作时间不明时先向作者确认，不使用文件时间推断。

## 哪些信息需要同步

| 操作 | 同步内容 |
| --- | --- |
| 新增文章 | 完整六字段 YAML、正文、实际配图和必要的互链 |
| 新增分类 | 文件夹；README 介绍可选 |
| 修改标题或摘要 | 当前文章元信息 |
| 修改正文或元信息 | 更新 `updated`，保持 `date` 不变 |
| 移动或重命名 | 引用该路径的文章、图片和文档链接 |
| 修改内容规则 | [内容指南](../SITE_CONTENT_GUIDE.md) 与相关契约 |

导航、搜索索引、标签和归档由内容管线生成，不编辑 `src/generated/`，不要求维护静态侧栏配置或分类数据库。

## 验证

开发模式自动反映新增、修改和删除。内容规则变动运行相关测试，发布前运行生产构建并部署 `frontend/dist/`。提交与推送另需用户明确指令。

详细字段、README 行为与图片格式见 [内容指南](../SITE_CONTENT_GUIDE.md)。
