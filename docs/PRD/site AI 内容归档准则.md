# AI Agent 内容归档准则

> 更新：2026-10-29。用于将新内容放入当前 `frontend/content/`，不维护静态目录快照。

## 归档顺序

1. 判断文章目标：知识沉淀、过程复盘，还是具体项目/工具介绍。
2. 查看对应栏目中已有目录，复用合适分类；需要时新建主题目录。
3. 一篇内容对应一个 Markdown，保留唯一正文。
4. 确认标题、可选元信息、配图目录和站内链接。
5. 在本地验证分类入口、文章与图片，记录结果。

## 栏目选择

- 长期知识与教程：`frontend/content/knowledge/`。
- 随笔、观点和阶段记录：`frontend/content/blog/`。
- 自有项目及推荐工具：`frontend/content/projects/`。

实际文件夹是分类事实源；不要在本准则复制完整目录或增加手工分类注册表。

## 文件要求

- 文件名使用清晰主题，需排序时增加数字前缀，允许中文。
- 标题取 frontmatter 的 `title`、正文首个一级标题或文件名。
- 元信息仅使用当前契约字段，不要求自定义 URL、作者列表或系列字段。
- 配图目录为 `文章名-images/`，引用以 Markdown 文件位置为基准。
- 二、三级标题生成本文目录；加粗段落不等同于标题。

## Agent 工作边界

- 遵守用户明确的创建和修改授权，保护已有工作区改动。
- 区分实测内容、资料整理和推断，不代写未经核实的个人经历、项目功能或许可。
- Fork 项目写明原项目和二次开发范围；获取与反馈链接以实际项目为准。
- 发布新内容不需要修改页面代码、导航配置或生成产物。
- 当前开发阶段不为历史数据增加兼容分支，使用新规范内容验证。
