# 博客架构与长期发展规划

> 当前修订：2026-10-29。本文描述现行架构方向，不作为新增功能或 Git 操作的执行授权。

## 定位与价值

箓川码笺面向在校学生，记录学习笔记、踩坑经验和项目实践，便于查找、复盘与分享。作者通过项目、笔记和复盘持续完善内容。

## 当前架构

- Vue 3、TypeScript、Vite 和 ByteMD 构成读者前端。
- `frontend/content/` 是唯一内容事实源，目录和文件构成导航与页面。
- 知识库、博客、项目采用同一套目录、分类列表和文章展示规则。
- 内容生成、资源解析和浏览器查询复用统一管线；当前读者端不需要运行时业务后端。

## 内容组织

| 内容 | 存放位置 |
| --- | --- |
| 长期技术知识、教程和参考 | `frontend/content/knowledge/` |
| 有时间背景的观点、过程与复盘 | `frontend/content/blog/` |
| 自有项目、二次开发与推荐工具 | `frontend/content/projects/` |

分类按实际内容逐级建立，不固定为一套必须手工登记的目录清单。文章标题、日期和标签遵循 [内容指南](../SITE_CONTENT_GUIDE.md)。

## 三种体验

- 用户：通过清晰分类、可读正文、可见的本文目录和搜索找到内容。
- 开发者：共用组件和单一内容事实源，避免手工同步导航与多份配置。
- AI Agent：使用 [文档索引](../DOCUMENTATION_INDEX.md) 定位职责、契约和验收命令。

当前为开发阶段，禁止为历史数据或旧 URL 引入兼容分支。调整路径后更新当前链接，使用新规范样例测试。

## 后续能力

全文搜索已有本地实现；评论与阅读统计、SEO/RSS/SSG、系列专题的状态见 [需求基线](个人技术站自研需求基线.md)。未实现能力须独立确认范围和验收，不通过添加 frontmatter 字段假定功能已经存在。

## 持续维护

- 持续补充知识、问题复盘和可核实的项目介绍，准确区分个人实践、资料整理和观点。
- 使用 Git 保存可审阅变更，提交和推送都按用户明确指令执行。
- 新规范直接用于数据与测试，不增加历史数据转换链。
- 路径、数据结构和公共组件变化及时更新工程规范，避免要求 Agent 阅读失效设计。
