# 桌面端适配新内容模型与单机交替编辑方案

## 1. 已确认需求

- 管理对象为 `frontend/content/`，重点是新建文档、读取文档、修改文档内容。
- 协作指同一台电脑上的桌面端、外部编辑器和 AI 交替修改 Markdown。
- 先检查并提出方案，用户明确指令后再修改代码。

## 3. 设计决策与范围

以下为方案建议，并非用户已确认的实现细节。

保留 Tauri + Vue + Python，不同时进行技术栈迁移。在 `admin-desktop/src-backend/` 内建立独立、精简的内容后端，复用旧后端中合适的路径检查、错误响应与版本校验思路；运行时不再导入 `old/` 或依赖已移走的 `admin/backend`。不整体复制旧后端及其 Docusaurus 工作流。

分两阶段验收：

1. 第一阶段：启动、内容发现、目录介绍、文档新建/读取/保存/删除、外部变更检测、冲突与未保存内容保护；调整相关页面和契约。
2. 第二阶段：图片写入与预览、重命名/移动及链接处理、新前端预览与构建、AI/Git 辅助能力对齐。另行明确细节并取得实施授权；第一阶段完成不等于整个桌面端适配完成。

第一阶段不引入账户协作、实时共同编辑、云同步、自动合并、数据库内容事实源、后台自动保存或自动 Git 提交。

## 4. 内容事实源与路径

- 唯一事实源为当前仓库 `frontend/content/` 内的文件与目录。正文与元数据不另存数据库，不直接编辑 `frontend/src/generated/`。
- 启动时依据明确的项目根目录参数，或从当前目录向上寻找同时包含 `frontend/content` 与 `admin-desktop` 的根目录；找不到就显示错误，不猜测到其他工作区，也不自动新建内容根目录。
- 文档定位使用相对内容根的完整路径，例如 `knowledge/技术研习/AI 探索/01-agent入门笔记.md`。不以 `docs/blog` 枚举或 Front Matter 中的 `slug` 定位。
- 栏目取一级目录，支持 `knowledge`、`blog`、`projects` 以及新增栏目。文件名、目录名保留中文、空格和数字前缀，不自动转拼音或将空格换成连字符。
- 以 `.`、`_` 开头的目录或文件不进入常规管理列表。文件系统路径经解析后必须位于内容根内，拒绝路径穿越、越界链接及非法文件名。
- `README.md`（忽略大小写）作为目录介绍管理，可读取和编辑，但不混入普通文章统计。普通 `index.md` 不自动视为目录介绍。
- 扫描、标题回退、排序、资源目录与空分类识别对齐 `frontend/README.md` 和当前内容扫描器。先运行一致性用例，遇到文档与实现分歧先列出，不顺带改变前台行为。
- 第一阶段新建文件限 `.md`。扫描器当前识别 `.mdx`，因此已存在的 `.mdx` 可以按原始文本读取、编辑，但不承诺执行 JSX。
- 根层 `.md` 文件也应能管理，不声称它必然对应前台可达页面。例如固定 `/about` 页当前不由 `content/about.md` 驱动。

## 5. 新建与编辑行为

### 新建

选择现有目录，输入实际文件名，再编辑 Markdown。标题可以来自可选 Front Matter、正文一级标题或文件名，不强制补齐旧站作者、slug、sidebar_position 等字段。

目录创建是明确操作：输入目标相对目录并确认后创建，不在保存时静默创建任意父目录。目录和文件冲突时返回具体错误，不覆盖已有内容。

新建提交整篇 `raw_content`，后端验证后原样写入，不再外包一层 Front Matter。创建使用排他语义，两个请求创建同名文件时只能有一个成功。

### 打开与保存

- 读取返回完整原始 Markdown 及文件内容摘要版本。前端分别保存读取基线和当前编辑缓冲。
- Markdown 文本是保存契约的主输入。后端用完整 YAML 解析器提取展示信息并校验，前端不再用简易 YAML 拆解后重组整篇内容。
- 修改正文时不重排 YAML、不丢弃未知字段、不自动补元数据；只修改正文的操作应保留原文档头。字段表单如保留，更新时必须保留无关字段和 YAML 注释，不能全量重新序列化破坏格式。
- 不因保存自动变更 `date`、`updated` 或其他字段；作者需要时在 Markdown 中明确修改。这样可减少桌面端、编辑器、AI 交替操作产生的无关差异。
- 不强制添加 Front Matter；已有无文档头的合法 Markdown 可以直接保存。无效 YAML 应返回可定位的错误，保留编辑缓冲和磁盘原文件。
- 保留原有 UTF-8 BOM 与换行风格；原样打开再保存应不产生无关变化，新建文件统一 UTF-8 无 BOM、LF。
- 文件版本使用磁盘字节内容的 SHA-256，而不是修改时间。保存携带读取时的 `expected_version`，成功后以服务端返回内容和版本建立新基线。
- 没有内容变化不写盘，不触发无意义的文件更新时间与前台重建。

### 删除

保留列表中已有的单文档删除能力：先展示目标相对路径并确认，删除时重新校验版本。文件已被外部修改则拒绝删除并提示刷新。第一阶段仅删除目标 Markdown，不连带清理图片、其他文件或非空目录。

## 6. 外部变更与冲突

| 当前状态 | 磁盘变化后的行为 |
| --- | --- |
| 编辑缓冲与读取基线一致 | 文件内容改变时自动重新读取，显示外部更新提示；尽量保持阅读位置。 |
| 编辑缓冲有未保存修改 | 保留编辑缓冲和原基线，提示外部变更，不自动刷新正文、不替换用于保存的基线版本。 |
| 保存时摘要与磁盘不一致 | 返回 409，保持本地未保存内容，提供本地文本与最新磁盘文本的对照。 |
| 外部删除或移动了当前文件 | 提示原路径不存在，保留编辑缓冲，不自动在旧路径重新创建。 |
| 用户切换文档、离开编辑器、关闭窗口 | 有未保存内容时允许保存、放弃或取消；保存失败或存在冲突时不能继续当作已保存离开。 |

冲突处理第一阶段提供：查看最新磁盘文本、复制本地修改、明确放弃本地修改并重新读取，以及另存为新文件。另存为仍使用排他创建，不隐式覆盖任何目标。手工合并后基于重新读取的最新版本保存，不提供默认强制覆盖或自动合并。

外部变更检测先采用轻量机制：窗口恢复焦点时刷新目录并检查当前文件；应用可见且当前文件打开时，每 2 秒检查其磁盘版本，手动刷新也可立即检查。为同一文件合并检查请求，避免旧响应覆盖新文档状态；文件尚未写完或 YAML 暂时无效时保留当前缓冲，待后续检查成功再更新。不另建全仓库后台索引服务。

后端自身的同路径写操作在同一个临界区内检查版本并执行写入；使用同目录临时文件与原子替换，失败不截断目标文件。检测以内容版本为准，桌面端自身保存产生的变动不重复提示外部冲突。

保证边界：这是交替编辑下的冲突检测。外部编辑器、AI 不参与同一写锁时，不能声称版本检查加原子替换可以绝对排除检查与替换之间的并发竞争。若未来需要严格同时写入保证，需要让各写入端遵循共同协议，另立需求。本期不因该极短窗口引入全局锁系统。

## 7. 第一阶段接口方向

沿用 `/api/v1`、snake_case 字段和统一错误结构。第一阶段核心接口如下；实施前补齐字段级契约并完成契约评审。

| 操作 | 方向 |
| --- | --- |
| 健康检查 | 返回后端就绪状态与所连接的内容根标识。 |
| 内容树/列表 | 返回实际目录、文档、目录介绍及展示信息，支持动态栏目；空目录可发现。 |
| 文档详情 | 输入安全的相对路径；返回 `relative_path`、`raw_content`、`version`、只读展示元数据。 |
| 文档版本 | 查询当前路径的存在状态与内容版本，供轻量外部变更检测。 |
| 新建文档 | 输入 `relative_path` 与 `raw_content`；目标已存在返回冲突。 |
| 保存文档 | 输入 `relative_path`、`raw_content`、`expected_version`；缺版本返回 428，版本不一致返回 409。 |
| 新建目录 | 显式输入相对目录；检查路径边界和目标冲突。 |
| 删除文档 | 输入目标相对路径、`expected_version` 与明确确认，仅操作单文件。 |

具体 HTTP 路径编码、分页及 DTO 由字段级契约明确；相对路径作为 JSON 或查询参数传递，避免依赖路由对嵌套编码斜杠的隐含处理。409/428/404 应在编辑器显示具体原因，不能统一吞成“保存失败”。

## 8. 页面、启动与旧能力处理

- 复用现有桌面壳、主题、文章列表、Markdown 源码编辑器和 Toast；不重做整体视觉。核实原 Editor.vue 已使用 textarea，ByteMD 仅为已有依赖，本期不新增富文本工具栏或预览。
- 文章列表增加实际目录选择、目录介绍区分与动态栏目筛选；仪表盘统计从当前内容树派生。
- 第一阶段移除原“注册表”导航入口；目录与标签信息在现有内容列表中呈现，不额外新建概览页面。目录和 Markdown 中的标签是事实源，不再维护额外 YAML 注册表。
- 第一阶段完成后，设置页不再展示可执行的 Docusaurus/侧边栏同步。媒体、AI 和旧发布接口尚未迁移时，相关操作明确显示“尚未适配”，不继续调用 `old/`，不返回伪造成功。
- 第二阶段才迁移这些辅助能力；AI 输出回到编辑缓冲，经同一版本检查保存，不另开绕过冲突检查的写入通道。
- 桌面 UI 开发使用现有 14200；Python 后端统一使用项目规定的 18000，开发模式保留热更新。新前端预览使用 3400；不因占用改端口。
- 端口被当前项目相同后端占用时可在校验内容根和服务身份后连接；不连接任意同端口 HTTP 服务，不自动终止无法确认归属的进程。桌面仅清理自己启动的子进程。
- 独立后端启动、认证及配置一并去除旧目录依赖。保留本机 HTTP 会话认证边界，不扩展账户系统，不将实际凭据写入前端源码或方案文档。
- 新增模块必须补 `AGENTS.md` 并同步导航；根导航中已失效的管理端路径仅在本次适配涉及的条目内修正。旧工程文档只作为参考，不扩大成全仓库文档重写。

## 9. 复用取舍

- 可复用思路与适用实现：安全路径解析、完整 YAML 解析、统一错误 DTO、内容摘要版本、文件快照与失败回滚。
- 必须剥离的耦合：docs/blog 工作流分派、博客一级分类限制、作者注册、侧边栏及首页索引自动改写、Docusaurus 配置同步。
- 前台内容扫描器用于定义一致性用例；不把生成清单当成写入源，不要求桌面编辑必须先启动前台。
- Python 与 Node 两种语言存在规则漂移风险，使用同一组临时内容样例验证两端的标题、README、隐藏目录、层级、排序和资源识别；避免业务层分散实现同一套规则。

## 10. 验收标准

所有写入验证在临时内容根执行，不用真实笔记作为破坏性测试数据。

1. 从当前仓库启动内容后端，不依赖 `old/admin`；桌面连接到正确的内容根。
2. 在带中文、空格和数字前缀的多层目录中新建 `.md`，Front Matter 只出现一次，前台扫描可发现文档。
3. 带标签数组、注释、嵌套字段、未知字段和无 Front Matter 的文档，修改正文后无关内容不丢失；不修改时保存不写盘。
4. 无本地修改时外部更新能刷新；有本地修改时外部更新保留缓冲；过期版本保存或删除均返回冲突。
5. 模拟外部删除、原子替换和读取期间变化，不自动重建旧文件，不将暂时读取失败视为用户放弃修改。
6. 切换文档、关闭窗口和保存失败后，本地修改受到明确保护；另存为不能覆盖已有文件。
7. 文档路径越界、无效 YAML、同名创建与写入失败可明确报错，失败后原文件保持完整。
8. README、动态栏目及空目录管理与前台规则对应；普通文章统计不含目录介绍。
9. 前后端契约测试、内容回归、桌面前端类型检查与相关构建通过；第二阶段未适配能力有明确可见状态。
