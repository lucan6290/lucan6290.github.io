基线 `f7b7aab988cbcf77d20ecd4034b337f31e5d5afc`。首次 fetch 后本地 main 领先 origin/main 41 个提交，落后 0 个。集成分支 `codex/xiaocan-delivery` 从该基线建立。真实远端操作需另行授权。

## 内容路径和写入契约

- 复用 ContentStore 内容根、Windows 约束、SHA-256 与写锁。新写入拒绝符号链接、junction、路径别名和目标冲突。配图目录由当前已保存 Markdown 的完整 stem 加 `-images` 派生。
- 统一以 Markdown 字节跨度解析链接目的地，保留正文其他字节、YAML、标题、锚点和链接标题。只处理站点支持的相对地址和能映射到已知源路由的站内绝对路径。链接、配图和知识图谱共用这一解析器。
- 图片以 `POST /api/v1/media` 导入，输入 `document_path, filename, data_base64`。返回图片条目及 `markdown`。`GET /api/v1/media?document_path=...` 浏览，读取复用 `GET /api/v1/images`。删除先 `GET /api/v1/media/delete-plan?path=...`，确认时发送 `DELETE /api/v1/media`，输入 `relative_path, plan_id, confirm`。失效预览返回 409。
- 移动使用 `POST /api/v1/moves/plan` 与 `POST /api/v1/moves`，输入 `source, destination, kind`，后者补 `plan_id`。计划显示文件移动、内容改写和公开路由变化。执行前重新构建计划比对，按写锁串行，执行失败执行回滚，失败响应报告无法回滚的具体状态。桌面保存、删除与移动共用锁。外部编辑器同时写入不受该锁控制，执行时发现变化停止，回滚避免覆盖后来写入。
- 回链与图谱接口只读并返回路径和边，继续使用当前文档访问权限。
- 范围验证先对实际字节和临时内容库写失败用例，继而后端全套、桌面前端全套和博客测试。操作成功后使用真实构建输出核对文章、链接和图片。

## 验收环境

本机 Windows 11 x64 已有 Node、pnpm、Python、Rust、WebView2 所需开发条件和 x64 SignTool。两处个人证书库均未发现代码签名证书，进程环境未发现签名、更新或服务配置。Windows Sandbox 可执行文件未发现，Hyper-V 服务存在，仍需确认可用且隔离的系统映像。AI 和公共互动生产验收需要明确可用的获授权环境。测试夹具、临时密钥或本机裸远端的通过结果单独记载。

执行顺序为独立模块与内容契约并行，然后串行接入共享入口与固定端口，最后独立审查、整体验收、干净检出复测与安全合并。原工作区已有 12 个未暂存路径及 6 个未跟踪路径；未暂存路径以 porcelain 清单为准，Cargo.toml 当前仅有工作区状态提示，需合并前再次比较字节与索引。
