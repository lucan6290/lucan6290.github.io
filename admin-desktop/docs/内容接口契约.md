# 第一阶段内容接口契约

状态：2026-10-29 方案确认后确定的实现契约。适用于独立桌面后端，不兼容旧 Docusaurus API。

## 连接与认证

仅监听 `127.0.0.1`。默认端口 `18000`，桌面启动时若端口被占用或预留，使用系统分配的端口。业务接口前缀 `/api/v1`。健康检查使用实际端口的 `GET /health`，返回 `{service: "xiaocancoding-content", api_version: 1, project_root, content_root}`，根路径均为绝对路径。

其余接口使用本次后端会话随机生成的 Bearer token。绑定成功后，后端写入 `{token, project_root, content_root, port}`。桌面为自有进程通过 `--session-file` 指定独立会话文件，也能通过 `session.json` 校验并复用独立启动的服务。会话文件不提交 Git，日志不打印 token。桌面通过 `get_backend_connection` 获取 `{base_url, token, content_root}`；浏览器开发默认使用 18000，手动输入 `session.json` 的 token。后端仅允许桌面 WebView 和 14200 开发源的 CORS，不允许通配源。

错误统一 `{code, message, details?}`。鉴权失败 401；路径非法、YAML 非法 400；文件不存在 404；版本冲突/同名 409；缺少版本 428。失败不得覆盖或截断原文件。

安装版通过 `--session-file` 把会话写入当前用户的本地应用数据目录。首次启动尚未选定仓库时，桌面命令 `get_backend_connection` 返回空；选择目录后传入 `projectRoot`，连接成功后记住该位置。 已连接时使用 `switch_blog_workspace({ projectRoot })` 切换，失败后可通过无参数的 `get_backend_connection` 刷新原工作区会话。参见 [工作区切换](工作区切换.md)。

## 数据类型

`DocumentSummary`: `{relative_path, name, title, section, kind: "article"|"introduction", tags: string[], description, date: string|null, updated: string|null, modified_at, version}`。

`DocumentDetail`: Summary 加 `{raw_content, frontmatter: object}`。`version` 为原始 UTF-8 文件字节的 SHA-256。读取返回保留 CRLF 与 BOM 的文本；字段提取不改变正文。已有无 Front Matter 文档可读取和编辑，YAML 非法返回可定位错误。标题回退：title → 首个非代码内一级标题 → 去数字前缀文件名。普通新文章和标准文章的日期维护见下节。

`ContentDirectory`: `{relative_path, name, label, section}`，内容根以空字符串表示，保留空目录；资源目录、隐藏路径按前台扫描规则排除。README 不计入普通文章。

## 端点

| 方法与路径 | 输入 | 输出 |
| --- | --- | --- |
| GET `/content` | 无 | `{directories: ContentDirectory[], documents: DocumentSummary[]}`，后端提供稳定目录/数字前缀顺序，前端使用与前台相同的本机 `localeCompare` 完成名称排序；一级栏目从 directories 派生 |
| GET `/images` | 查询 `path` | 受会话保护的图片字节及对应 MIME；路径须为内容根内允许的相对图片路径 |
| GET `/documents` | 查询 `path` | DocumentDetail |
| GET `/documents/version` | 查询 `path` | `{exists: boolean, version: string|null}`；原路径不存在时返回 exists=false |
| POST `/documents` | JSON `{relative_path, raw_content, article?: boolean}` | 201 DocumentDetail；只建 `.md`，父目录必须已存在；排他创建；article 默认 true，显式 false 为说明文档或保留历史元信息的复制 |
| PUT `/documents` | JSON `{relative_path, raw_content, expected_version, article?: boolean}` | DocumentDetail；可编辑已有 `.md/.mdx`；用途省略则自动识别，true 为本次按文章维护，false 为本次按说明原文保存；无变化不写盘 |
| DELETE `/documents` | JSON `{relative_path, expected_version, confirm: true}` | `{deleted: relative_path}`；不删关联资源 |
| POST `/directories` | JSON `{relative_path}` | 201 ContentDirectory；显式递归创建目录，目标已存在返回 409 |

路径必须使用 `/` 分隔的安全相对路径，禁止绝对路径、`.`/`..` 片段、隐藏片段、Windows 非法/保留名称和解析后越出内容根的符号链接。不静默替换中文、空格或编号。

`GET /content` 还接受最多 200 字符的可选查询 `query`。按空白拆词，不区分大小写，每词须匹配文档标题、路径、摘要、标签或 Markdown 内容。查询只筛选文档，目录和排序不变。

## 协作语义

后端写操作串行检查版本及原子替换；新建不得覆盖。无改动保存不重写换行或 BOM。原文 UTF-8 BOM 可在 JSON 内传递，编辑器将其作为隐藏前缀保留，显示文本不含 BOM；CRLF 在编辑缓冲中可规范为 LF，保存时按读取基线恢复换行。

前端轮询与焦点检查不得把最新版本悄悄设为有未保存修改文档的基线。冲突保留本地文本，展示磁盘文本，允许明确放弃并重载、复制、另存为新文件。不把外部删除当成新建机会。对于不遵循共同锁协议的外部工具，本阶段不提供严格同时写入保证。

## 普通文章六字段

本次明确授权补充并替代第一阶段“不自动生成头部或更新日期”的旧行为：

- 新建默认普通文章：前端自动生成 `title`、`date`、`updated`、`description`、`tags`、`sticky`，固定顺序；字符串为双引号，标签为行内字符串数组，默认 `[]`，置顶为布尔值默认 false。标题和摘要由作者填写，空值不能作为普通文章保存；标题应与正文首个一级标题一致。
- 进入新建写作状态时记录真实北京时间，精确到秒且带 `+08:00`，新建初始 date=updated。不用示例日期、文件时间或首次点击保存的时间替代开始写作时间。
- POST 默认校验新普通文章的必填字段、顺序、格式、类型、标签去重和日期。允许作者额外字段位于六字段之后，不生成旧站 authors/slug/sidebar_position 或同义日期字段，也不默默丢弃未知字段。
- `README.md`、`AGENTS.md` 大小写无关自动豁免；其它工程说明、设计文档由作者选择“说明文档”（article=false），不根据文件名猜测用途。仅无用户修改时可自动切换模板，脏缓冲始终保留。
- 另存为是复制：默认 article=false，保留来源中的真实 date/updated；不把历史文档缺失的开始时间补成当前时间。
- PUT 先校验 expected_version。省略 article 时，磁盘已具备完整六字段的普通文章在内容或其它元信息真实改变后仅定点改写 updated 值，使用不早于 date 的真实北京时间；date 与磁盘不一致时返回具体错误，不能静默改变开始时间。删除必填字段同样报错。
- 已有文档可选择“本次编辑用途”：自动识别、普通文章或说明文档。显式 article=false 保留原文与日期，说明文档即使自带六字段也不会被强制套用文章规则；true 则明确按文章校验。缺失历史 date 必须由作者填写，后端不猜测。新建选择说明后在当前编辑会话继续按说明保存；重新打开时默认自动识别，必要时可再次明确用途。用途是本次作者意图，不额外持久化为注册表或向 Markdown 加新字段。
- 已有文章保存只检查字段语义，不批量重排旧 YAML、块状标签和注释；无实际变化或仅人为改 updated 不写盘。历史字段不完整文档继续按原文编辑，不自动补历史日期。
- 响应包含服务端维护后的 raw_content/version。保存请求期间继续输入的内容必须保留；只有本地 updated 仍等于发送值时，才能合并服务端 updated 行，防止旧响应覆盖用户正在编辑的字段。
- 共享 updated 的 YAML 引用或无法独立定位 updated 的 merge 写法需要作者改成独立字段后保存；返回明确校验错误，不能返回 500 或间接修改 date、未知元信息。当前输入已修好时，不因旧快照的引用结构阻止修复保存。

## 文档配图接口

接口使用同一会话认证和内容锁。配图目录为文章同级的完整文件名去掉扩展名再加 -images。文件名安全验证与文章相同，额外禁止目录分隔符；同名图片按不区分大小写避免覆盖。新上传的字节先写临时文件再发布。

| 方法与路径 | 输入 | 输出 |
| --- | --- | --- |
| GET /media | 查询 document_path | {images: MediaImage[]} |
| POST /media | JSON {document_path, filename, data_base64} | 201 MediaImage |
| GET /media/delete-plan | 查询 path | {relative_path, plan_id, references: [{relative_path, count}]} |
| DELETE /media | JSON {relative_path, plan_id, confirm: true} | {deleted: relative_path} |

MediaImage 包含 relative_path、name、mime_type、size、markdown。查看图片仍用 GET /images。单张最大 12 MiB，上传检查格式与扩展名，SVG 只允许安全图形子集。删除计划包含图片版本和当前引用文档的版本，计划变化时返回 409。删除保留 Markdown 原文。

## 移动与文档链接

| 方法与路径 | 输入 | 输出 |
| --- | --- | --- |
| POST /moves/plan | JSON {source, destination, kind: "document" 或 "directory"} | {source, destination, kind, plan_id, moves, files, routes} |
| POST /moves | 预览输入加 plan_id | 已执行的计划 |
| GET /links | 无 | {documents: string[], edges: [{source, target}]} |

源、目标均为内容根相对路径，目标父目录须已存在。同名占用、保留目录、符号链接和目录联接会被拒绝。文档移动同步移动同名配图目录；移动分类时整棵目录一并移动。moves、files、routes 项均有 before 和 after，files 还标记 rewritten。链接变更只改 Markdown 目的地，保留 YAML、链接标题、查询和锚点。目录 URL 以及指向搬迁文章的已知站内 URL 随计划更新。分类仍在原位时，其绝对分类 URL 继续指向原分类。

执行重算计划，SHA-256 绑定实际移动字节及受影响文档版本。普通读写和移动共用服务内锁，文件替换使用同目录临时文件。执行中检测到冲突或文件系统失败时回滚已执行步骤。外部程序写入无法受该锁约束，回滚遇到后来改动时保留其数据并报告需核对的路径。日期不因路径变更或机械链接修复而改变。知识图谱与反向链接只含当前内容库内可解析到文档的连接。


## 文章表单

POST /article-form/read 从 raw_content 读取 title、description、tags、sticky。POST /article-form/patch 接收同一份 raw_content 及 values，返回更新后的 raw_content。两项操作均不接触磁盘，使用现有会话鉴权。表单只更新四个字段及与标题配套的首个一级标题，保留日期、未知字段、YAML 注释、BOM 和换行。共享的 YAML 值需要在源码中处理。前端只将结果应用到相同版本的编辑缓冲，保存仍走原版本校验。

## 评审

需求与方案：用户已确认。契约/架构检查：原始 Markdown 单一写入契约、版本必填、路径边界、排他创建、运行根校验、旧能力显式停用，与已确认方案一致；实施及测试需继续向本契约验证。
