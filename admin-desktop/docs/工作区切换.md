# 桌面工作区切换

设置页发起切换之前，沿用编辑器的保存、放弃、取消流程。新选的目录可以是仓库根目录或其 `frontend/content`。

## 原生契约

- `switch_blog_workspace({ projectRoot })` 返回通过健康与会话认证的 `{ base_url, token, content_root }`。安装版成功后才持久化目录，开发版保留原有启动发现与后端源码约束。
- 先解析路径并检查候选后端入口，再考虑停止当前自有内容后端。只在固定 18000 尝试启动或连接。外部服务不会被停止。
- 后端启动、会话验证或目录记录失败时，清理本次新进程。若旧后端由应用拥有，则恢复旧工作区及其服务。失败返回原因，恢复失败时附带恢复错误。
- 切换失败后，调用无参数的 `get_backend_connection` 获取旧工作区的有效会话。恢复可能生成新的 token。成功后停止旧工作区的自有预览，清除旧页面内容并重新加载新工作区。

## 实施与验证

- 需求检查覆盖用户选择、编辑保护和失败回退。方案复用现有 18000 验证，安装记录只随成功连接改变，契约及所有权架构检查通过。
- 先用临时目录与进程夹具覆盖候选预检、同工作区选择、外部占用和回退，再实现原生事务。运行 Rust 检查、回归和桌面构建，并审查认证与清理路径。
