新增 docs 或 blog 文章时，Agent 必须遵循本规范。涵盖文件位置、命名、Front Matter、同步维护清单与后端数据同步。

## 1. 文章类型与目录结构

| 类型 | 根目录 | 层级 | 说明 |
| --- | --- | --- | --- |
| docs（知识库） | `site/docs/` | 一级分类 → 二级分类 → 文章 | 体系化技术笔记、系列教程 |
| blog（博客） | `site/blog/` | 一级分类 → 文章（无二级分类） | 阶段记录、踩坑复盘、成长随笔 |

docs 目录结构示例：

```text
site/docs/
├── index.md                          # docs 总目录页
├── tech-study/                       # 一级分类（英文 slug）
│   ├── index.md                      # 一级分类目录页
│   ├── AI 探索/                      # 二级分类（中文）
│   │   ├── claude-code项目开发规范.md # 文章（中文文件名）
│   │   └── ...
│   └── Jetson Orin Nano/
│       └── ...
└── project-practice/
    └── ...
```

blog 目录结构示例：

```text
site/blog/
├── index.md                          # blog 总目录页
├── AI观察/                           # 一级分类（中文目录，不需要 index.md）
│   ├── AI正在重构你的行业.md
│   └── ...
└── 随笔感想/
    └── ...
```

### 关键差异

| 项 | docs | blog |
| --- | --- | --- |
| 一级分类目录名 | 英文 slug（如 `tech-study`） | 中文（如 `AI观察`） |
| 二级分类 | 有 | 无 |
| 分类目录页 `index.md` | 每级分类都需要 | 不需要 |
| 侧边栏登记 | `sidebars.ts` | `blogSidebars.ts` |
| 导航入口 | `docusaurus.config.ts` 知识库 dropdown | `docusaurus.config.ts` 博客 dropdown |

## 2. 文件命名规则

> 基础规则见 `GLOBAL_STANDARDS.md` 第 4 节。

| 层级 | 命名规则 | 示例 |
| --- | --- | --- |
| docs 一级分类目录 | 英文 slug | `tech-study`、`project-practice` |
| docs 二级分类目录 | 中文 | `AI 探索`、`开发工具入门` |
| docs 文章文件名 | 中文，无日期前缀 | `claude-code项目开发规范.md` |
| blog 一级分类目录 | 中文 | `AI观察`、`随笔感想` |
| blog 文章文件名 | 建议 `YYYY-MM-DD-slug.md`，也允许纯中文 | `AI正在重构你的行业.md` |

通用约束：

- 允许中文、英文、数字、连字符、下划线。
- 不能是 `.` 或 `..`，不能含路径分隔符 `/` `\`。
- 不能含 Windows 非法字符 `< > : " | ? *`。
- 不能以空格或点号结尾。

## 3. Front Matter 规范

### 3.1 docs 文章 Front Matter

模板源：`admin/backend/data/content-schema/dacs_template.md`

```yaml
---
title: 文章标题
authors: lucan
date: 2026-06-29T10:00:00+08:00
last_update:
  date: 2026-06-29T10:00:00+08:00
  author: lucan
description: 文章说明
sidebar_position: 1
---
```

| 字段 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `title` | 是 | string | 文章标题（中文） |
| `authors` | 是 | string | 作者 ID，须存在于 `site/docs/authors.yml` |
| `date` | 是 | ISO 8601 | 创建日期，含时区（如 `2026-06-29T10:00:00+08:00`） |
| `last_update.date` | 是 | ISO 8601 | 最后更新日期 |
| `last_update.author` | 是 | string | 最后更新者 |
| `description` | 是 | string | 文章摘要，用于 SEO 与目录页展示 |
| `sidebar_position` | 是 | number | 侧边栏排序位置 |

### 3.2 blog 文章 Front Matter

模板源：`admin/backend/data/content-schema/blog_template.md`

```yaml
---
slug: article-slug
title: 文章标题
authors: lucan
date: 2026-06-29T10:00:00+08:00
last_update:
  date: 2026-06-29T10:00:00+08:00
  author: lucan
description: 文章说明
tags:
  - 标签一
  - 标签二
---
```

| 字段 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `slug` | 是 | string | 文章 URL 路径片段（单个路径片段，允许中文） |
| `title` | 是 | string | 文章标题（中文） |
| `authors` | 是 | string | 作者 ID，须存在于 `site/blog/authors.yml` |
| `date` | 是 | ISO 8601 | 创建日期，至少以 `YYYY-MM-DD` 开头 |
| `last_update.date` | 是 | ISO 8601 | 最后更新日期 |
| `last_update.author` | 是 | string | 最后更新者 |
| `description` | 是 | string | 文章摘要 |
| `tags` | 是 | string[] | 标签列表，须已注册于 `tags.yml` |

### 3.3 时间格式

> 详见 `GLOBAL_STANDARDS.md` 第 5 节。

- 统一 ISO 8601 字符串并显式含时区：`2026-06-29T18:00:00+08:00`。
- blog `date` 至少以 `YYYY-MM-DD` 开头。
- 后端默认时区 `Asia/Shanghai`。

## 4. 同步维护清单

### 4.1 docs 同步清单

| 文件 | 何时同步 | 说明 |
| --- | --- | --- |
| `site/docs/index.md` | **所有 docs 变动** | docs 总目录页，记录全部一级分类、二级分类、文章 |
| `site/docs/<一级分类>/index.md` | 该分类下变动时 | 一级分类目录页，记录该分类下的二级分类与文章 |
| `site/docs/<一级分类>/<二级分类>/index.md` | 该二级分类下变动时 | 每个二级分类必须有 `index.md` |
| `site/sidebars.ts` | docs 分类或文章变动 | 登记文章 ID，格式 `<一级分类>/<二级分类>/<文章名>` |
| `site/docusaurus.config.ts` | **仅一级分类变动** | 知识库导航 dropdown 新增/删除/重命名入口 |
| `admin/backend/data/content-schema/categories.yml` | 一级分类新增/删除/重命名/改显示名 | 分类注册表 |
| `admin/backend/data/registry_index.sqlite3` | docs 分类和文章变动完成后 | 重建/刷新查询索引 |

### 4.2 blog 同步清单

| 文件 | 何时同步 | 说明 |
| --- | --- | --- |
| `site/blog/index.md` | **所有 blog 变动** | blog 总目录页，记录全部一级分类与文章 |
| `site/blogSidebars.ts` | blog 分类或文章变动 | 侧边栏结构（label/path/to/items） |
| `site/docusaurus.config.ts` | **仅一级分类变动** | 博客导航 dropdown 新增/删除/重命名入口 |
| `admin/backend/data/content-schema/categories.yml` | 一级分类变动；文章落到新分类时确保分类已写入 | 分类注册表 |
| `admin/backend/data/content-schema/tags.yml` | 文章涉及新标签时 | 标签注册表 |
| `admin/backend/data/registry_index.sqlite3` | blog 分类和文章变动完成后 | 重建/刷新查询索引 |

注意：blog 一级分类目录下**不需要 `index.md`**，创建新分类时只建目录。

## 5. 后端数据同步

### 5.1 `categories.yml`（分类注册表）

路径：`admin/backend/data/content-schema/categories.yml`

| 字段 | 说明 |
| --- | --- |
| `type` | `docs` 或 `blog` |
| `slug` | 分类 slug（单个路径片段） |
| `path` | 路径数组（一级分类为单元素，二级分类为多元素） |
| `label` | 显示名 |
| `aliases` | 别名列表（可选） |
| `description` | 分类描述（可选） |
| `cover` | 封面图路径（可选，如 `/img/covers/tech-study.svg`） |
| `sort_order` | 排序权重 |
| `enabled` | 是否启用 |

同步时机：一级分类新增/删除/重命名/改显示名时必须同步。

### 5.2 `tags.yml`（标签注册表）

路径：`admin/backend/data/content-schema/tags.yml`

| 字段 | 说明 |
| --- | --- |
| `slug` | 标签 slug（英文或 `tag-` 前缀哈希） |
| `label` | 标签显示名 |
| `description` | 描述（可选） |

同步时机：blog 文章涉及新标签时写入。前端不硬编码标签名，以后端接口转换结果为准。

### 5.3 `registry_index.sqlite3`（查询索引）

路径：`admin/backend/data/registry_index.sqlite3`

- 这是**派生数据**（可删除重建），不承载事实源语义。
- 所有文章/分类变动完成后需重建/刷新。
- 重建方式：通过后端接口或后端启动时自动扫描。

## 6. 新建文章操作流程

### 6.1 新建 docs 文章（分类已存在）

1. 新建文章文件：`site/docs/<一级分类>/<二级分类>/<文章名>.md`。
2. 填写 Front Matter（见第 3.1 节）。
3. 修改 `site/sidebars.ts`，在对应二级分类的 `items` 中加入文章 ID：

   ```ts
   'tech-study/AI 探索/claude-code项目开发规范'
   ```

4. 同步更新三个 `index.md`：二级分类目录页、一级分类目录页、docs 总目录页。
5. 刷新 `registry_index.sqlite3`。

### 6.2 新建 docs 二级分类

1. 新建二级目录与文章文件。
2. 新建二级分类目录页 `index.md`（**必须创建**）。
3. 修改 `site/sidebars.ts`，在一级分类 `items` 中新增 `category`：

   ```ts
   {
     type: 'category',
     label: '二级分类名',
     collapsed: false,
     items: ['一级分类/二级分类/文章名'],
   }
   ```

4. 同步更新一级分类 `index.md` 和 docs 总目录页 `index.md`。
5. 刷新 `registry_index.sqlite3`。

### 6.3 新建 docs 一级分类

1. 新建一级目录、二级目录、文章文件。
2. 新建二级分类 `index.md`。
3. 新建一级分类 `index.md`。
4. 修改 `site/sidebars.ts`，新增 sidebar 分组（含一级分类 category + 二级分类 category + 文章 ID）。
5. 修改 `site/docusaurus.config.ts`，在知识库 dropdown 加入入口：

   ```ts
   { label: '分类显示名', to: '/docs/分类slug' }
   ```

6. 修改 `categories.yml`，新增分类条目。
7. 更新 docs 总目录页 `index.md`。
8. 刷新 `registry_index.sqlite3`。

### 6.4 新建 blog 文章（分类已存在）

1. 新建文章文件：`site/blog/<一级分类>/<文章名>.md`。
2. 填写 Front Matter（见第 3.2 节），确保 `slug`、`title`、`authors`、`date`、`description`、`tags` 完整。
3. 更新 `site/blog/index.md` 总目录页。
4. 更新 `site/blogSidebars.ts`，在对应分类的 `items` 中加入文章条目：

   ```ts
   { label: '文章标题', to: '/blog/slug' }
   ```

5. 如果涉及新标签，写入 `tags.yml`。
6. 如果 `authors` 不在 `site/blog/authors.yml` 中，新增作者条目。
7. 刷新 `registry_index.sqlite3`。

### 6.5 新建 blog 一级分类

1. 新建分类目录（**不需要 `index.md`**）。
2. 修改 `site/docusaurus.config.ts`，在博客 dropdown 加入口：

   ```ts
   { label: '分类显示名', to: '/blog/分类slug' }
   ```

3. 修改 `categories.yml`，新增 `type: blog` 的分类条目。
4. 更新 `site/blog/index.md` 总目录页。
5. 后续按第 6.4 节流程加入文章。
6. 刷新 `registry_index.sqlite3`。

### 6.6 新增博客作者

如果 `authors` 不是已有的，修改 `site/blog/authors.yml`：

```yaml
newAuthor:
  name: 作者名
  title: 作者说明
  url: https://example.com
  image_url: https://example.com/avatar.png
```

### 6.7 移动/重命名文章

1. 移动/重命名文章文件。
2. 修改对应侧边栏（`sidebars.ts` 或 `blogSidebars.ts`），更新文章 ID 或条目信息。
3. 全站检查并替换旧链接（`docusaurus.config.ts`、其他文章、各级 `index.md` 目录页）。
4. 刷新 `registry_index.sqlite3`。

## 7. 检查清单

### docs 文章

- [ ] 文件路径符合命名规则（一级分类英文 slug，二级分类与文章名中文）。
- [ ] Front Matter 含 `title`、`authors`、`date`、`last_update`、`description`、`sidebar_position`。
- [ ] 已在 `site/sidebars.ts` 登记文章 ID，且与真实路径一致。
- [ ] 已同步三个 `index.md`（二级分类、一级分类、docs 总目录页）。
- [ ] 新一级分类已更新 `docusaurus.config.ts` 和 `categories.yml`。
- [ ] 移动文章已替换全站旧链接。
- [ ] 已刷新 `registry_index.sqlite3`。

### blog 文章

- [ ] 文件名符合命名规则（建议 `YYYY-MM-DD-slug.md` 或纯中文）。
- [ ] Front Matter 含 `slug`、`title`、`authors`、`date`、`last_update`、`description`、`tags`。
- [ ] `authors` 已存在于 `site/blog/authors.yml`。
- [ ] 已同步 `site/blog/index.md` 和 `site/blogSidebars.ts`。
- [ ] 新标签已写入 `tags.yml`。
- [ ] 已刷新 `registry_index.sqlite3`。

### 最终验证

```bash
cd site
npm run build
```

构建报 broken links 时优先检查：

- `site/sidebars.ts` 中 docs 文章 ID 与真实路径是否一致。
- `site/blogSidebars.ts` 中 blog 文章信息是否一致。
- `site/docusaurus.config.ts` 中 `to` 是否与文章路由一致。
- 各级 `index.md` 目录页链接是否仍指向有效路径。
