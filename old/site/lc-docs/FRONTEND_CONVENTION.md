## 1. 站点工程

| 工程 | 框架 | 语言 | 说明 |

站点与管理前端技术栈独立，规范分别约束，站点有独立的前端约定。

## 1.1 命名规范（DECLARED）

> 来源：profile_default（Skill Technology Profile）+ project_decision（用户决策）

| 项 | 规则 | 来源 |
| --- | --- | --- |
| 变量/函数/方法 | `camelCase` | profile_default |
| 组件命名 | `PascalCase` | profile_default |
| 类型安全 | `strict` 模式，避免 `any` | profile_default |
| 类型来源 | 从 API Contract 派生（`derive_types_from_contract`），不各自维护 | profile_default |
| API 字段 | `snake_case`（直接消费后端契约，见 `API_CONTRACT.md`（管理端治理文档）） | project_decision |

转换边界：

- 前端是「契约消费方」，不做通用命名转换。
- 反模式（avoid）：前端拦截器做全局 snakeCase/camelCase 运行时字符串改写（`frontend_runtime_contract_conversion`）；如需字段映射，仅针对单个接口显式映射。

## 2. 站点工程（site/）

### 2.1 结构约定

| 目录 | 职责 | 是否生成 AGENTS.md |
| --- | --- | --- |
| `blog/`、`docs/` | 内容事实源（Markdown/MDX） | 否（内容目录不生成） |
| `src/` | 站点源码（components/pages/theme/css） | 是 |
| `src/components/` | 自定义 React 组件 | 是 |
| `src/pages/` | 独立页面（首页/about/projects） | 是 |
| `src/theme/` | Docusaurus 主题 swizzle 覆写 | 是 |
| `src/css/` | 全局样式 | 是 |
| `plugins/` | 站点插件 | 是 |
| `static/` | 静态资源（img/favicon 等） | 否 |
| `docusaurus.config.ts` | 站点配置与导航 | — |
| `sidebars.ts` | docs 侧边栏 | — |
| `blogSidebars.ts` | blog 侧边栏 | — |

### 2.2 配置管理约定

| 配置文件 | 管理范围 | 何时修改 |
| --- | --- | --- |
| `docusaurus.config.ts` | 顶部导航菜单、站点元信息、preset/plugin 配置、主题配置 | **仅一级分类变动**（新增/删除/重命名/改显示名）时改导航 dropdown |
| `sidebars.ts` | docs 侧边栏结构（一级分类 → 二级分类 → 文章 ID） | docs 分类或文章变动时同步 |
| `blogSidebars.ts` | blog 侧边栏结构（一级分类 → 文章列表，无二级分类） | blog 分类或文章变动时同步 |

规则：

- `docusaurus.config.ts` 的 navbar dropdown 按模块组织（知识库、博客、项目、关于），每个 dropdown 的 `items` 对应该模块的一级分类入口。
- `sidebars.ts` 中 docs 文章 ID 格式为 `<一级分类>/<二级分类>/<文章名>`（无扩展名），须与文件真实路径一致。
- `blogSidebars.ts` 是纯 TypeScript 数组（非 Docusaurus 配置函数），每项含 `label`/`path`/`to`/`items`。
- 新增 docs 文章必须登记进 `sidebars.ts`；新增 blog 文章必须登记进 `blogSidebars.ts`。
- 详细同步规则见 `SITE_CONTENT_GUIDE.md`。

### 2.3 页面与样式约定

#### CSS 变量体系（`src/css/custom.css`）

站点全局样式通过 CSS 变量管理，定义在 `:root` 和 `html[data-theme='dark']` 中：

| 变量类别 | 示例 | 用途 |
| --- | --- | --- |
| 主题色 | `--ifm-color-primary` 系列（含 dark/light/darker/lightest） | 站点主色及衍生色阶 |
| 字体 | `--ifm-font-family-base`（霞鹜文楷）、`--ifm-font-family-monospace`（JetBrains Mono） | 正文与代码字体 |
| 排版 | `--ifm-font-size-base`（16px）、`--ifm-line-height-base`（1.78） | 基础字号与行高 |
| 布局 | `--ifm-navbar-height`（54px）、`--ifm-global-radius`（8px） | 导航栏高度与圆角 |
| 滚动条 | `--site-scrollbar-thumb`、`--site-scrollbar-track` | 自定义滚动条样式 |
| 暗色模式 | `html[data-theme='dark']` 覆写 | 暗色主题色与背景 |

规则：

- 全局样式修改在 `src/css/custom.css` 中进行，通过覆写 `--ifm-*` 变量实现，不直接修改 Docusaurus 主题源码。
- 暗色模式色值在 `html[data-theme='dark']` 块中覆写，保持与亮色模式对应的语义。
- 自定义变量用 `--site-*` 前缀，不与 `--ifm-*` 冲突。

#### CSS Modules

- 页面级样式使用 CSS Modules（`*.module.css`），与页面组件同目录同名。
- 示例：`src/pages/index.tsx` + `src/pages/index.module.css`。
- 不在组件中使用内联样式（inline style）处理可复用样式。

### 2.4 组件开发约定

| 约定 | 规则 |
| --- | --- |
| 组件类型 | React 函数组件 + Hooks，不使用 Class 组件 |
| 命名 | 组件名 `PascalCase`，文件名与组件名一致 |
| 目录结构 | 每个组件一个目录：`ComponentName/index.tsx` + 可选 `AGENTS.md` |
| 类型安全 | TypeScript `strict` 模式，避免 `any` |
| 样式 | 组件级样式用 CSS Modules，全局样式用 `custom.css` 变量 |
| 逻辑复用 | 跨组件复用逻辑抽自定义 Hook（`useXxx`），副作用隔离 |
| 单一职责 | 组件只负责视图渲染与局部状态，不承载跨页业务逻辑 |

反模式（avoid）：

- 把副作用/数据获取散写在组件 render 中。
- 在组件内硬编码分类/标签中文名（以后端接口转换结果为准）。
- 修改 `node_modules` 内主题源码。

### 2.5 主题覆写约定

- 使用 `src/theme/` 做 Docusaurus 主题 swizzle，覆写默认主题组件。
- 现有覆写：`BlogSidebar/`（博客侧边栏）、`DocRoot/`（文档根布局）、`DocSidebar/`（文档侧边栏）、`Footer/`（页脚）。
- 覆写组件保持原组件接口签名，不破坏 Docusaurus 主题契约。
- 新增覆写时先确认目标组件是否支持 swizzle（`docusaurus swizzle` 命令检查）。

### 2.6 插件开发约定

- 自定义插件放在 `plugins/` 目录，每个插件一个子目录 + `index.js` + `AGENTS.md`。
- 现有插件：`blog-category-pages/`（博客分类页插件，为 blog 一级分类生成独立列表页）。
- 插件在 `docusaurus.config.ts` 的 `plugins` 数组中注册。
- 插件不直接操作内容文件，只读取并生成路由/页面。

### 2.7 静态资源约定

- 静态资源放在 `static/` 目录，通过根路径引用（如 `/img/favicon.png`）。
- 文章封面图放在 `static/img/covers/`，分类封面在 `categories.yml` 中引用路径。
- 图片上传的扩展名/大小/安全校验规则见 `GLOBAL_STANDARDS.md` 第 6 节。

## 3. 跨端一致性

- 分类、标签、Front Matter 规则以后端 `content-schema` 为准，前端只消费后端接口转换后的结果。
- 当前读者站点的内容字段见 [站点内容契约](../../../docs/API_CONTRACT.md)。

## 4. 组件职责与 Feature 边界

- 组件单一职责：只负责视图渲染、局部状态、事件处理，不承载跨页业务逻辑。
- Feature（业务功能）跨组件/视图组织时，复用同一 store 与 API 层，不复制逻辑。
- 页面（views）编排组件与数据流；组件（components）可复用，不直接耦合路由。

## 5. Composable / Hook（逻辑复用）

- React：复用逻辑用自定义 `hook`（`useXxx`），副作用隔离。
- 反模式：把副作用/数据获取散写在组件模板或 render 里。

## 6. 工具与静态资源（Utility / Asset）

- `utils/` 放纯函数工具，无副作用、可单测。
- 静态资源：`site/static/`（站点静态资源；管理端有独立的 `assets/` 目录）。
- 不把可复用逻辑写死在视图组件里。

## 7. 测试约定（Testing）

- 组件/交互测试建议用 React Testing Library（site）。
- 优先测纯函数（`utils/`）与 store，再测关键交互组件。
- 命名 `*.spec.ts` 或 `*.test.ts`，与被测文件同目录或集中 `__tests__/`。
