## 1.1 命名规范（跨两套前端，DECLARED）

| --- | --- | --- |
| 变量/函数/方法 | `camelCase` | profile_default |

转换边界：

- 前端是「契约消费方」，不做通用命名转换。
- 反模式（avoid）：前端拦截器做全局 snakeCase/camelCase 运行时字符串改写（`frontend_runtime_contract_conversion`）；如需字段映射，仅针对单个接口显式映射。

## 2. 管理前端（admin/frontend/）

### 2.1 技术栈

Vue 3、Vite、Naive UI、Pinia、Vue Router（hash）、ByteMD（Markdown 编辑器）、axios。

### 2.2 目录职责

| 目录 | 职责 |
| --- | --- |
| `api/` | 后端调用层（`local.ts` 的 `LocalAPIClient`，`index.ts` 导出 `BlogAPI` 类型） |
| `components/` | 通用/业务组件（`AIAssistant.vue`、`NewPostModal.vue`、`ai-writing/*`） |
| `stores/` | Pinia 状态（aiConfig、aiWriting、categories、knowledgeIndex、posts、settings） |
| `types/` | TS 类型（api.ts、local.ts、ai-writing.ts） |
| `utils/` | 工具（auth、frontmatter、postDisplay、approvalPolicy、aiWritingValidation） |
| `views/` | 页面（Dashboard、Posts、Editor、Registry、AIWriting、Media、Settings、Login） |

### 2.3 路由

- hash 路由，base `/admin/`（`createWebHashHistory('/admin/')`）。
- 除 `/login` 外均 `meta.requiresAuth`，`router.beforeEach` 统一鉴权跳转。

### 2.4 状态管理

- 全局共享状态用 Pinia `stores/`；页面局部状态用组件内 `ref`/`reactive`。
- 跨页面数据（文章列表、分类、设置、AI 配置）进 store；纯展示派生值用 `utils/postDisplay.ts` 等纯函数计算。

### 2.5 API 集成

- 统一走 `LocalAPIClient`（`src/api/local.ts`），禁止在各 view 直接散写 axios。
- `baseURL` 取 `VITE_API_BASE_URL || 'http://127.0.0.1:18000'`，前缀 `/api/v1`。
- 请求拦截器自动附加 `Authorization: Bearer <token>`；响应 401 自动清除本地会话。
- 网络/5xx 自动重试（默认 3 次，指数退避）；错误统一映射为 `LocalAPIError`。
- 前端创建文章应调用组合接口 `POST /api/v1/articles`，不要拆成多步同步调用。

### 2.6 类型与契约

- 后端 DTO 对应类型集中在 `src/types/api.ts`，AI 写作在 `types/ai-writing.ts`。
- 字段名与后端 snake_case 保持一致（`category_path`、`expected_version`、`dry_run`），仅在映射到 `PostInfo`/`PostDetail` 时转 camelCase。
- 分类显示名（`category_label`）、状态（`displayStatus`）以后端返回为准，前端不硬编码分类 slug 中文名。

### 2.7 错误与加载态

- 请求失败统一经 `LocalAPIError`（code/message/details），UI 按 code 提示。
- 列表/详情区分 loading / empty / error 三态；危险操作先展示 `dry_run` 计划再确认。

## 3. 跨端一致性

- 分类、标签、Front Matter 规则以后端 `content-schema` 为准，前端只消费后端接口转换后的结果。
- 字段语义/类型/枚举在 Database → Backend → API → Frontend 保持一致（详见 `API_CONTRACT.md`）。

## 4. 组件职责与 Feature 边界

- 组件单一职责：只负责视图渲染、局部状态、事件处理，不承载跨页业务逻辑。
- Feature（业务功能）跨组件/视图组织时，复用同一 store 与 API 层，不复制逻辑。
- 页面（views）编排组件与数据流；组件（components）可复用，不直接耦合路由。

## 5. Composable / Hook（逻辑复用）

- Vue3：跨组件复用逻辑抽 `composable`（`useXxx`），副作用隔离；纯函数逻辑集中在 `utils/`。
- 反模式：把副作用/数据获取散写在组件模板或 render 里。

## 6. 工具与静态资源（Utility / Asset）

- `utils/` 放纯函数工具（auth、frontmatter、postDisplay、approvalPolicy、aiWritingValidation），无副作用、可单测。
- 静态资源：`admin/frontend/src/assets/`（前端资源）；站点静态资源由站点端规范另行约束。
- 不把可复用逻辑写死在视图组件里。

## 7. 测试约定（Testing）

- 组件/交互测试建议用 Vitest + Vue Test Utils。
- 优先测纯函数（`utils/`）与 store，再测关键交互组件。
- 命名 `*.spec.ts` 或 `*.test.ts`，与被测文件同目录或集中 `__tests__/`。
