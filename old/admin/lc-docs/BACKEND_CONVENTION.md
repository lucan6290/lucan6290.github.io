## 1. 技术栈与约束

- Python `>=3.10`，FastAPI `0.115.0`，Uvicorn，Pydantic v2，PyYAML，python-multipart。
- 包名 `scr`（非 `app`）；入口 `scr/main.py`，必须用 `python -m scr.main` 或 `uvicorn scr.main:app` 启动。
- 依赖双份：`pyproject.toml`（`[project].dependencies`）+ `requirements.txt`（镜像，需同步）。
- 代码风格：ruff，`target-version=py310`，`line-length=120`，双引号、space 缩进、LF 行尾。

## 2. 分层与依赖方向

```text
api/v1/endpoints   # HTTP 层：参数解析、路由，只做薄编排
      │
      ▼
application/…/workflows  # 应用编排：跨文件/跨服务、带快照与回滚
      │
      ▼
services/…         # 业务能力：单一领域服务
      │
      ▼
infrastructure/…   # 文件系统、注册表/SQLite 等基础能力
```

规则：

- 依赖方向自上而下，不允许反向依赖（infrastructure 不 import services）。
- 「单一文件/单一规则维护」放对应业务域服务；「跨文件、跨服务、有回滚要求」放 `application/content/workflows/`。
- `core/` 提供跨切面能力（配置、鉴权、异常、日志、中间件、安全）；`schemas/` 是 DTO，`models/` 是领域模型。

## 3. 模块职责速查

| 目录 | 职责 |
| --- | --- |
| `api/v1/endpoints/` | 每业务域一个文件（articles/categories/tags/sidebars/schema/registry_index/validation/build/deploy/git_sync/docusaurus_config/sync/auth/ai_models/agents/health） |
| `api/v1/router.py` | 汇总挂载到 `/v1`，再由 main 以 `/api` 前缀引入 |
| `application/content/workflows/` | `article_workflow` 按 type 分发到 `docs_article_workflow` / `blog_article_workflow` / `category_workflow` |
| `services/content/` | articles / blog / categories / docusaurus / sidebars / sync / validation |
| `services/site/` | build / deploy / git_sync |
| `services/ai/` | editor / knowledge / tools / writing + llm_adapter + model_config_service |
| `infrastructure/filesystem/` | filesystem_service、markdown_service |
| `infrastructure/registry/` | YAML 注册表 + SQLite 索引 + 索引器/查询/仓库 |

## 4. 路由与端点约定

- 统一前缀 `/api/v1`，完整路径 `/api/v1/<resource>`。
- 每端点文件内定义 `router = APIRouter(prefix="/<resource>", tags=["<resource>"])`，在 `router.py` 中 `include_router`。
- 多路由拆分：`agents.router` 与 `agents.approval_router` 分别承载「发起任务」与「继续审批」语义。

## 5. 命名约定（DECLARED）

> 来源：profile_default（Skill Technology Profile）+ project_decision（用户决策）

| 项 | 规则 | 来源 |
| --- | --- | --- |
| 变量/函数/方法 | `snake_case`（PEP 8） | profile_default |
| 文件/模块 | `snake_case` | profile_default |
| 类名 | `PascalCase` | profile_default |
| 常量/枚举 | `UPPER_SNAKE_CASE` | profile_default |
| 类型注解 | `type_hints`（PEP 484），强制标注 | profile_default |
| 格式化 | ruff（black 亦可） | profile_default |
| import 排序 | ruff（isort 亦可） | profile_default |
| API 字段 | `snake_case`（与 Python/DB 一致，见 `API_CONTRACT.md`） | project_decision |

- DTO 以 `DTO` 结尾（`ArticleSummaryDTO`、`ErrorResponseDTO`）。
- 请求体 DTO：`XxxCreateDTO` / `XxxUpdateDTO`；动作请求：`XxxRequestDTO`；结果：`XxxResultDTO`。
- DTO 与持久化/领域模型分离（`dto_separation`），接口对象不直接复用 ORM/文件模型。
- **反模式（avoid）**：Python 代码内使用 `camelCase`（`camelCase_in_python_code`）。

## 6. 异常与错误响应

- 统一异常基类 `AppError`（`core/exceptions.py`），子类覆盖默认 `status_code`/`code`/`message`：`NotFoundError`(404)、`BadRequestError`(400)、`ConflictError`(409)、`PreconditionRequiredError`(428)。
- 全局异常处理器将异常转为统一 `ErrorResponseDTO`：

```json
{ "code": "article_not_found", "message": "文章不存在。", "request_id": "…", "details": {} }
```

- 通用错误码：`request_validation_error`(422)、`internal_error`(500)；各接口在文档中只列其特有错误码。
- 业务错误码全小写 snake_case（`article_not_found`、`version_conflict`、`confirmation_required`…）。

## 7. 成功响应约定

- 成功响应直接返回 DTO 或数组，不包 `{success, data}` 信封。
- 状态码：GET/PUT/DELETE=`200`，POST 创建=`201`，动作型 POST=`200`，异步=`202` 或 `200`。

## 8. 配置管理

- `scr/core/config.py`：`dataclass(frozen=True) Settings`，进程启动加载一次为模块级 `settings` 单例。
- 通过环境变量 `LUCHUAN_*` 覆盖（`LUCHUAN_PROJECT_ROOT`、`LUCHUAN_CORS_ORIGINS`、`LUCHUAN_ENV`、`LUCHUAN_ADMIN_*`、`LUCHUAN_AUTH_SECRET` 等）。
- 自行加载 `admin/backend/.env`，已存在的系统环境变量优先。

## 9. 鉴权实现

- `core/auth.py`：HMAC-SHA256 签名 token（`payload.signature`），`admin_auth_middleware` 保护 `/api/v1`（白名单 `health`、`auth/login`）。
- 登录端点 `POST /api/v1/auth/login` 签发 `LoginResponseDTO`（access_token、expires_at、username）；`GET /api/v1/auth/me` 返回当前会话。

## 10. 事务/回滚（内容工作流）

- `application/content/workflows/` 中 `create_article()` 先快照可能被改的文件，再按顺序写文件、同步侧边栏/首页/导航/索引，失败时按快照回滚。
- 具体同步链路与回滚策略见 `admin/docs/内容工作流接口说明.md`。

## 11. 测试约定

- pytest，`tests/` 目录，文件名 `test_*.py`，`addopts=-ra`。
- 契约测试命名 `test_*_api_contracts.py`；工作流/回滚测试（`test_docs_article_workflow.py`、`test_blog_sidebar_and_nav.py`）覆盖关键编排。
- 运行：`cd admin/backend && python -m pytest`。

## 12. 新增后端能力的决策

- 单一文件/单一规则 → 对应业务域 `services/`。
- 跨文件/跨服务/需回滚 → `application/content/workflows/`。
- 新端点 → `api/v1/endpoints/<domain>.py` + `schemas/<domain>.py` + 注册进 `router.py`，并补齐接口文档（见 `admin/docs/管理员后端接口文档.md` 第 17 节检查清单）。

## 13. 领域模型与 DTO（Domain / Entity）

- `models/`（如 `models/article.py` 的 `ArticleType`）是领域模型，只存放业务概念（枚举、值对象），不直接对外暴露。
- `schemas/` 是接口输入输出 DTO（Pydantic），与领域模型分离（`dto_separation`）。
- 领域枚举继承 `str, Enum`，可直接 JSON 序列化并参与查询参数校验。
- 反模式（avoid）：领域/持久化模型直接作为 API 响应（`orm_leaking_to_api`）。

## 14. 持久化与 Repository（Repository）

- `infrastructure/registry/` 是唯一直接访问 SQLite 与 YAML 注册表的层（`registry_sqlite_repository.py`、`registry_yaml_service.py`）。
- 文件系统读写集中在 `infrastructure/filesystem/`（`filesystem_service.py`、`markdown_service.py`）。
- 上层（services/workflows）通过基础设施能力访问存储，不泄漏 SQLite 行、SQL、文件句柄等细节。
- SQLite 索引（`registry_index.sqlite3`）是可删除重建的派生数据，不承载事实源语义。

## 15. 对象映射（Mapper）

- 存储记录 ↔ DTO / 领域对象的映射必须显式、集中，不做隐式转换。
- 已有映射：`registry_sqlite_mappers.py`（`item_from_row`）、`registry_sqlite_repository.py`、`model_config_service.py` 的 `_to_public`。
- 映射规则显式记录，转换逻辑不散落在端点层。

## 16. 入参校验（Validation）

- 请求校验在 Pydantic boundary 完成（`schemas/` DTO），端点层信任框架保证，不重复校验。
- 业务规则校验放 Service 层（如 `article_validation_service.py`、`validation_service.py`），与传输校验分离。
- 校验失败通过统一异常（`AppError` 子类）与 `ErrorResponseDTO` 返回。

## 17. 依赖注入（DI）

- 端点通过 `FastAPI Depends` 注入服务，服务工厂集中在 `api/v1/dependencies.py`（`get_xxx_service()` + `lru_cache` 单例）。
- 工厂返回可替换的服务，测试用 `dependency_overrides` 覆盖，不在端点内直接 `Service()`。
- 组合服务通过工厂显式组装（如 `EditorAgentService(article_service=..., llm_adapter=...)`）。

## 18. 序列化与转换边界

- 跨层命名转换归属后端 contract boundary，由 Pydantic schema 完成。
- 本项目 API 字段统一 snake_case（`project_decision`），与 Python/DB 一致，无需 `alias_generator` 做 case 转换。
- 反模式（avoid）：DB 字段直接作为 API 字段（`db_field_directly_as_api_field`）。

## 19. 日志（Logging）

- `core/logging.py` 用 `dictConfig` 统一配置控制台日志，格式 `时间 级别 [日志器名] 消息`。
- `request_context_middleware` 注入 `request_id`（沿用 `X-Request-ID` 或生成），回写响应头并记录请求方法/路径/状态码/耗时。
- 关键路径与异常记录日志；不记录 token、密码等敏感信息（token 经 `access_token` query 参数传递，日志只记 path 不记 query）。
