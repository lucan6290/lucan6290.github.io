# 内容工作流接口说明

本文档说明 `POST /api/v1/articles` 在创建 docs/blog 文章时实际触发的后端工作流，以及这些同步能力在代码中的拆分边界。

## 1. 总览

创建文章接口不是单纯写入一个 Markdown 文件。它是一个应用层工作流，由 `ArticleWorkflowService` 根据 `type` 分发到不同编排类：

| type | 工作流类 | 主要职责 |
| --- | --- | --- |
| `docs` | `DocsArticleWorkflow` | 创建知识库文章，同步 docs 侧边栏、一级分类目录页和 SQLite 索引 |
| `blog` | `BlogArticleWorkflow` | 创建博客文章，同步博客首页、博客侧边栏、顶部博客导航、标签/分类注册表和 SQLite 索引 |

接口入口：

```text
POST /api/v1/articles
```

代码入口：

```text
admin/backend/scr/api/v1/endpoints/articles.py
admin/backend/scr/services/content/workflows/article_workflow.py
```

## 2. Blog 创建文章

### 2.1 请求约束

blog 创建请求必须满足：

| 字段 | 规则 |
| --- | --- |
| `type` | 必须为 `blog` |
| `title` | 必填 |
| `slug` | 必填，用作文件名和前端 `/blog/{slug}` 路由 |
| `category_path` | 必须且只能包含一个一级分类 |
| `authors` | 必填，且必须存在于 `site/blog/authors.yml` |
| `tags` | 可为空数组；存在的新标签会写入标签注册表 |
| `date` | 可选；缺省时由后端生成当前上海时区时间 |

当前 blog 文件路径规则：

```text
site/blog/<一级分类>/<slug>.md
```

不会再生成 `YYYY-MM-DD-slug.md` 这种日期前缀文件名。

### 2.2 同步链路

`BlogArticleWorkflow.create_article()` 按顺序执行：

1. 校验 `slug`、blog 一级分类路径和作者。
2. 快照可能被修改的文件。
3. 确保标签注册表存在并写入新标签。
4. 确保 blog 一级分类目录和分类注册表存在。
5. 写入正式文章文件。
6. 同步顶部博客导航中的一级分类入口。
7. 重写 `site/blogSidebars.ts`。
8. 同步 `site/blog/index.md` 分类目录。
9. 重建管理端 SQLite 索引。
10. 返回创建后的文章详情。

### 2.3 会维护的文件

| 文件/目录 | 触发条件 | 说明 |
| --- | --- | --- |
| `site/blog/<category>/<slug>.md` | 每次创建 | 正式文章文件 |
| `site/blog/<category>/` | 分类不存在时 | 创建一级分类目录 |
| `admin/backend/data/content-schema/categories.yml` | 分类不存在时 | 写入 blog 分类注册表 |
| `admin/backend/data/content-schema/tags.yml` | tags 中有未登记标签时 | 写入标签注册表 |
| `site/blog/index.md` | 每次创建后同步 | 只维护博客首页分类目录，不把首页当文章列表项 |
| `site/blogSidebars.ts` | 每次创建后同步 | 维护 blog 一级分类和分类下文章项 |
| `site/docusaurus.config.ts` | 文件存在时 | 在博客顶部导航中追加缺失的一级分类入口 |
| `admin/backend/data/registry_index.sqlite3` | 每次创建后重建 | 管理端搜索、分页、统计索引 |

### 2.4 回滚策略

如果后半段同步失败，工作流会尽量恢复到调用前状态：

| 已修改内容 | 回滚方式 |
| --- | --- |
| 新建文章文件 | 删除 |
| 新建空分类目录 | 删除 |
| `categories.yml` | 用快照恢复，原本不存在则删除 |
| `tags.yml` | 用快照恢复，原本不存在则删除 |
| `site/blog/index.md` | 用快照恢复 |
| `site/blogSidebars.ts` | 用快照恢复 |
| `site/docusaurus.config.ts` | 用快照恢复 |

对应回归测试：

```text
admin/backend/tests/test_blog_sidebar_and_nav.py
```

## 3. Docs 创建文章

### 3.1 请求约束

docs 创建请求必须满足：

| 字段 | 规则 |
| --- | --- |
| `type` | 必须为 `docs` |
| `title` | 必填 |
| `slug` | 必填，用作 docs 文件名片段 |
| `category_path` | 可为空；非空时目标分类必须已存在 |
| `sidebar_position` | 可选，写入 Front Matter |
| `authors` / `date` | 可选，会写入 Front Matter |

当前 docs 文件路径规则：

```text
site/docs/<category_path...>/<slug>.md
```

docs 创建文章不会隐式创建分类。分类创建应通过分类接口完成，因为 docs 一级分类还会维护目录页、知识库顶部导航和 `sidebars.ts` 分类结构。

### 3.2 同步链路

`DocsArticleWorkflow.create_article()` 按顺序执行：

1. 计算目标相对路径。
2. 快照 `site/sidebars.ts` 和所属一级分类 `index.md`。
3. 校验目标 docs 分类已存在。
4. 写入正式文章文件。
5. 将新 doc id 写入已有 docs 侧边栏分类位置。
6. 如果一级分类 `index.md` 存在，则插入或更新文章链接。
7. 重建管理端 SQLite 索引。
8. 返回创建后的文章详情。

### 3.3 会维护的文件

| 文件/目录 | 触发条件 | 说明 |
| --- | --- | --- |
| `site/docs/<category_path>/<slug>.md` | 每次创建 | 正式文章文件 |
| `site/sidebars.ts` | 每次创建 | 将新 doc id 插入对应分类 |
| `site/docs/<top-category>/index.md` | 存在时 | 维护一级分类目录页文章链接 |
| `admin/backend/data/registry_index.sqlite3` | 每次创建后重建 | 管理端搜索、分页、统计索引 |

### 3.4 回滚策略

如果后半段同步失败，工作流会恢复：

| 已修改内容 | 回滚方式 |
| --- | --- |
| 新建文章文件 | 删除 |
| `site/sidebars.ts` | 用快照恢复 |
| `site/docs/<top-category>/index.md` | 用快照恢复，原本不存在则删除 |

对应回归测试：

```text
admin/backend/tests/test_docs_article_workflow.py
```

## 4. 独立能力服务

工作流只负责“编排”。具体能力拆在业务子包中：

| 能力 | 主要服务 |
| --- | --- |
| 文章详情、列表、保存、删除、移动 | `articles/*` |
| docs 文章文件创建 | `articles/docs_article_service.py` |
| blog 文章文件创建 | `articles/blog_article_service.py` |
| docs 一级分类目录页 | `categories/category_index_service.py` |
| 分类注册表与目录 | `categories/*` |
| docs 侧边栏 | `sidebars/sidebar_service.py` |
| blog 侧边栏 | `sidebars/blog_sidebar_service.py` |
| blog 首页 | `blog/blog_index_service.py` |
| blog 顶部导航 | `blog/blog_nav_service.py` |
| Docusaurus 配置对账 | `docusaurus/*` |
| 标签注册表 | `registry/tag_service.py` |
| SQLite 索引 | `registry/registry_index_service.py` |
| 文件和 Markdown 基础能力 | `filesystem/*` |

新增功能时优先判断它是“单一能力服务”还是“跨能力编排工作流”：

- 单一文件或单一规则维护，放在对应业务域服务中。
- 跨文件、跨服务、有回滚要求的流程，放在 `workflows/` 中。

## 5. 前端调用建议

前端创建文章时优先调用组合接口：

```text
POST /api/v1/articles
```

不要让前端拆成“先写文章、再同步首页、再同步侧边栏、再重建索引”的多次调用。原因：

- 后端才能统一维护文件快照和失败回滚。
- 前端不需要知道 Docusaurus 文件之间的耦合细节。
- 单个组合接口更容易测试和保证一致性。

单独同步接口仍然保留，用于人工对账、修复旧数据或管理端工具按钮，例如：

| 场景 | 建议接口 |
| --- | --- |
| 重新同步 docs/blog 侧边栏 | `/api/v1/sidebars/*` |
| 重建 SQLite 索引 | `/api/v1/registry-index/sync` |
| 对账 Docusaurus 顶部导航 | `/api/v1/docusaurus-config/*` |
| 同步标签注册表 | `/api/v1/tags/sync` |
