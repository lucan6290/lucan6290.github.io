# frontend — 箓川码笺自研前端

> 箓川码笺当前使用的自研前端，以 `content/` 中的本地 Markdown 为唯一内容事实源。

## 技术栈

- Vite 6 + Vue 3.5 + TypeScript + Vue Router
- ByteMD（GFM + highlight + KaTeX + Mermaid）只读渲染
- CSS design tokens（`src/styles/tokens.css`），支持浅色与深色主题

## 开发原则

- 每次修改必须同时改善用户体验、开发体验和 AI Agent 使用体验，并通过与改动相符的验证确保不破坏现有功能。
- 当前项目处于开发阶段，禁止为了历史数据增加兼容代码分支。不符合当前规范的旧数据可以直接丢弃或替换，使用符合新规范的数据测试。

## 主要目录与入口

```tex
frontend/
├── content/                    # Markdown 与配套图片，内容事实源
│   ├── knowledge/              # 知识库
│   ├── blog/                   # 博客
│   └── projects/               # 项目与工具介绍
├── scripts/
│   ├── build-content.mjs       # 内容生成命令入口
│   └── lib/                   # 内容扫描实现与回归测试
├── src/
│   ├── views/                 # 首页、分类、文章、关于等页面
│   ├── components/            # 导航、侧栏、Markdown、本文目录等
│   ├── composables/           # 内容访问、路径解析和主题逻辑
│   ├── config/nav.ts          # 已知栏目名称、顺序、Logo 与外链
│   ├── styles/                # 全局样式与主题变量
│   ├── vite/contentManifestPlugin.ts
│   └── generated/             # 自动生成，已忽略，禁止手动编辑
└── dist/                      # 生产构建产物
```

三栏通过 `ContentRoute.vue` 共用 `CategoryView.vue`、`ArticleView.vue` 和 `MarkdownRenderer.vue`。固定“关于”页由 `AboutPage.vue` 渲染。

## 本地开发

```powershell
cd frontend
pnpm install
pnpm dev          # http://127.0.0.1:3400/
```

端口固定为 **3400**，不自动换端口。先检查占用情况，确认是本项目已运行的服务后再停止对应进程：

```powershell
netstat -ano | Select-String ':3400'
Stop-Process -Id <PID> -Force
```

开发服务和 `pnpm preview` 共用该端口，不能同时运行。

## 内容写作规范

- 内容事实源：`content/` 目录
- 目录 = 分类页，`.md` = 内容页，任意嵌套
- 文件名数字前缀排序：`01-xxx.md`；无前缀按标题排序；也可切换为“创建时间”排序，未填写时间的文章排在有时间文章之后
- 新建普通文章必须包含固定顺序的六字段：`title` / `date` / `updated` / `description` / `tags` / `sticky`，完整规则见 [内容指南](../docs/SITE_CONTENT_GUIDE.md#统一-yaml-头部frontmatter)
- 置顶：`sticky: true` 恒排最前
- `content/` 一级目录自动生成顶部栏目，子目录和 Markdown 按对应栏目的目录规则进入导航与列表。

### 复制笔记即可展示

将知识笔记放进 `content/knowledge/`，随笔放进 `content/blog/`，项目或工具介绍放进 `content/projects/`。每个主题或项目单独一个 Markdown 文件，文件夹代表分类：

```text
content/
├── knowledge/技术研习/Python学习/
│   ├── README.md
│   ├── 01-环境安装.md
│   ├── 01-环境安装-images/
│   │   └── 环境配置.png
│   └── 02-基础语法.md
├── blog/随笔感想/
│   └── 01-学习复盘.md
└── projects/
    ├── README.md
    ├── 01-我的项目/
    │   ├── 01-TerminalVoice.md
    │   ├── 02-AgentKit.md
    │   └── 03-get_jobs.md
    └── 02-开源项目与工具/
        ├── 01-Orca.md
        └── 02-Hexhub.md
```

- 新建普通文章必须填写六字段 YAML，`title` 与正文一级标题一致。当前解析器仍保留 `title`、正文首个 `# 一级标题`、去掉数字前缀的文件名这一标题回退顺序，但不作为新文章省略字段的依据。
- `README.md`（不区分大小写）是所在目录的介绍，不是普通文章，不进入文章列表、标签和归档。三栏首页与内部分类的具体展示方式见下方「顶部栏目与目录」。
- `[下一章](./02-基础语法.md)` 自动跳转到站内文章，`[分类介绍](./README.md)` 跳转到分类页；支持 `../`、中文、空格（链接地址可用 `%20`）及查询参数、锚点。
- 文内标题锚点保留中文和数字、英文转小写、空格转 `-`、去掉标点；同名标题追加 `-1`、`-2`。例如 `## 安装步骤` 对应 `#安装步骤`。
- 一级空目录仍生成栏目。知识库、博客和项目内的空分类也保留；仅含图片等资源的目录不生成分类。
- 以 `.` 或 `_` 开头的文件、目录不进入内容树。目录名与文件名构成 URL，移动或重命名后需要同步更新相关链接。
- `date` 表示开始写作时间，创建后不变；`updated` 表示最近一次内容修改时间，新建时与 `date` 相同。日期统一使用带 `+08:00` 的完整时间字符串，不依赖文件时间。

六字段全部保留；`title`、`description` 非空，没有标签时填 `tags: []`，`sticky` 默认 `false`。修改正文或元信息时维护 `updated`，不因文件复制、移动或部署改写日期。站点扫描器不回写 YAML；桌面端新建普通文章会生成模板并校验，已有完整六字段文章实际修改时维护 `updated`。字段含义以 [内容指南](../docs/SITE_CONTENT_GUIDE.md#统一-yaml-头部frontmatter) 为准。

### 图片命名与引用

新内容统一使用 **`文章名-images/`**，与 Markdown 放在同一目录。文章名取文件名去掉 `.md` 后的部分，例如 `01-环境安装.md` 对应 `01-环境安装-images/`。

```markdown
![环境配置截图](./01-环境安装-images/环境配置.png)
```

- 图片路径按 Markdown 源文件位置解析，支持中文、空格、`../` 与网络图片地址。开发和生产构建共用这一处理方式。
- 本地图片放在 `content/` 内；复制文章时连同配图目录一起复制，使用相对路径引用，不使用 `E:\...` 等电脑本地绝对路径。
- 支持 PNG、JPG/JPEG、GIF、SVG、WebP、AVIF、BMP、ICO；PDF 可作为附件链接。
- `文章名-images/` 中只存放配图等资源，不放 Markdown 文章；仅含资源的目录不作为分类。

### 右下角“本文目录”

知识库、博客、项目的文章页共用 `FloatToc.vue`，自动收集正文中的 `## 二级标题` 与 `### 三级标题`。有这些标题时，右下角显示“本文目录”按钮，点击后展开章节列表并支持跳转；窄屏下按钮显示在底部操作栏。

`**功能亮点**` 只是加粗文字，不会生成目录项，应使用 `## 功能亮点`。只有 `# 一级标题` 或没有二、三级标题的文章不会显示目录按钮；分类介绍 README 不使用文章页的浮动目录。

### 内容自动更新

运行 `pnpm dev` 时，新增、修改、删除 Markdown、目录或图片会触发内容监控，重新生成内容清单并刷新页面。生产构建会先执行 `prebuild` 生成内容，再完成类型检查与打包。

生成内容包括 `src/generated/` 下的内容清单、搜索索引、标签和归档数据，禁止手动编辑。公网静态网站需要重新构建并部署 `dist/`，仅复制到本地不会更新线上。

本阶段以标准 Markdown 为支持范围，不执行 MDX JSX，也不转换 Obsidian 双链、Word 或原始 HTML 内的资源地址。

## 顶部栏目与目录

| 一级目录 | 顶部栏目 | 首页内容 |
| --- | --- | --- |
| `content/knowledge/` | 知识库 | README 正文；无正文时自动展示直属分类与文章 |
| `content/blog/` | 博客 | README 正文；无正文时自动展示直属分类与文章 |
| `content/projects/` | 项目 | README 正文；无正文时自动展示直属分类与文章 |
| 固定页面 `/about` | 关于 | `src/views/AboutPage.vue` |
| `content/学习路线/` 等新目录 | 文件夹名称 | README（可选）与文章列表 |

- 新建一级目录即可出现顶部入口，无需修改导航或路由代码，空目录也可进入。
- “关于”是固定页面，点击顶部导航直接进入，不依赖内容目录。
- 窄窗口点击顶部“栏目”按钮展开导航，选择页面后自动收起。
- 知识库、博客和项目下拉菜单只显示首页及直属一级文件夹。二级及更深文件夹显示在分类页和左侧目录；分类页只列直属子分类和直属文章，不将后代文档平铺。其他栏目下拉仍显示首页及直属子分类、文章。
- 知识库层级示例：`knowledge/Java/集合框架/HashMap.md` → 下拉选 Java → 分类页选集合框架 → 打开 HashMap。新建空分类也可按此路径逐级进入。
- 知识库、博客和项目共用目录与文章展示规则：首页有非空 `README.md` 时，只在主区域显示介绍，侧栏自动显示一级分类；README 不存在或内容为空时，自动显示栏目标题、直属子分类和直属文章。
- 进入分类后，主区域显示该目录的 README（如有）、直属子分类与直属文章；侧栏只展示当前所属一级分类的目录树。建议将文章放进分类文件夹，通过分类列表或侧栏进入独立文章页。
- 三栏文章页共用标题、作者、日期、正文、阅读进度、本文目录和上一篇／下一篇组件；上一篇／下一篇按同一直属目录内的文章顺序生成。
- 项目内容示例：`projects/01-我的项目/01-TerminalVoice.md` 和 `projects/02-开源项目与工具/01-Orca.md`。新增目录或 Markdown 后会自动进入分类与导航，无需修改页面代码。
- 现有四栏按知识库、博客、项目、关于排列，新增栏目追加在后；新增栏目间遵循内容树的数字前缀及名称顺序。
- 重命名、删除目录会同步改变栏目及地址；隐藏和资源目录不生成栏目。
- `src/config/nav.ts` 仅保留四栏中文名称、固定顺序、Logo 和右侧外链配置。
- `tags` 和 `archive` 在未创建同名内容目录时显示内置标签、归档工具页；如果创建同名一级目录，则该地址优先展示内容栏目。

### GitHub Pages 部署

`.github/workflows/deploy.yml` 在推送 `main` 或手动运行时，使用 Node.js 24 和 pnpm 10.21.0 安装锁定依赖、运行测试、构建并发布 `frontend/dist/`。仓库 Settings → Pages 的 Source 需设为 **GitHub Actions**。

- 构建使用 Pages 返回的站点 origin 生成 canonical、站点地图和 RSS。构建 base 取自 `actions/configure-pages` 的 `base_path`：当前 `lucan6290.github.io` 用户站为 `/`；项目站自动使用 `/<仓库名>/`；自定义域名以 Pages 返回值为准，无需硬编码仓库名。
- 路由、导航、文内 Markdown 链接、Logo 和构建资源遵循相同 base。文档内容仍使用站内逻辑路径（如 `/projects/...`）或相对路径，不在内容中写死部署前缀。
- 构建会为全部分类、文章、关于及未被内容栏目占用的标签/归档页输出对应目录的 `index.html`。直接打开或刷新文章可由 Pages 命中真实文件；无法作为可移植目录名的标签继续通过 Vue Router 访问。Pages 可能补充 URL 末尾的 `/`，查询参数和章节锚点保留。
- `404.html` 用于未知地址，`.nojekyll` 保留静态资源目录。文章、栏目和系列页还会写入预渲染正文，关于、标签和归档保留 Vue 入口。
- 本地验证子路径可执行 `pnpm build --base /仓库名/`；实际用户站使用 `pnpm build`。本地预览的 SPA 回退不能替代对生成目录和静态 HTTP 状态的检查。
- 文章评论使用 [Utterances](https://utteranc.es/)，仓库须启用 Issues 并安装 [Utterances GitHub App](https://github.com/apps/utterances)。读者使用 GitHub 账号登录后发言，每篇文章按 Markdown 源路径关联独立 Issue。移动或重命名源文件时，若要保留评论，需要把原 Issue 的标题更新为新路径对应的检索词。
- 如需启用累计阅读量或在线管理，在仓库变量中设置公开的 HTTPS 服务地址 `VITE_PUBLIC_SERVICE_URL`。配置及鉴权见 [站点互动服务](service/README.md)。

内容迁移由作者从旧站复制到新前端内容目录。

## 读者搜索

- 点击顶部“搜索”，输入中文或英文关键词，可检索文章标题、标签、摘要和正文（含代码关键词）。多个关键词共同匹配，标题命中优先，英文支持大小写忽略与前缀匹配；最多展示 30 条结果。
- 结果显示标题、摘要和所属栏目，点击进入文章。手机端同样提供搜索入口；支持 Tab 选择、Enter 打开、Esc 关闭，关闭后返回搜索按钮。
- 搜索由浏览器中的 MiniSearch 执行，首次打开搜索窗口时加载引擎和索引，无需后端或搜索服务。README 分类介绍、隐藏内容和没有独立文章路由的根目录占位文件不参与文章搜索。
- 搜索索引由内容管线自动生成，开发时随内容刷新；线上修改文章后需重新构建、部署 `dist/`。
